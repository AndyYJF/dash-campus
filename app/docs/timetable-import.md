# SDCT1 课表导入

入口：计划 → 可用时间、课程与缓冲 → 批量导入课表。

粘贴 SDCT1 文本或选择 UTF-8 `.txt`，填写第一教学周的周一日期与课程时区，点击「解析并预览」核对，再「确认导入课表」。没有第一周日期不能按真实学期导入。预览不写数据库、不调用模型、不会创建任务或发送邮件。

格式：

```text
SDCT1
T=18
P=1,08:15-09:00;2,09:10-09:55
C=示例课程|教师|教室|1|1-2|3-18|A|-
```

- T：学期周数1–60；P：唯一节次时间表（1–30），时间顺序递增且不重叠。
- C：课程名、教师、地点、周几1–7、节次、教学周、周标记、占位字段共八项。
- 节次/教学周使用数字、逗号、闭区间；A全部、O单周、E双周，以教学周编号为准。
- 最后一项目前仅支持 `-`。未知标记、未定义节次、倒置范围、非周一/不存在的日期等报出错误，不猜测或忽略。
- 连续节次包含课间休息；离散节次分别生成活动。连续教学周合成有效日期范围；例如6,10拆成两条单周规则，不占用第7–9周。

教师与地点存入活动名称，与课程名一起保留。schema仍为16，复用fixed_events和现有容量/排程冲突计算。仅追加活动，完全相同的规则跳过；修改课程内容后重新导入会生成不同活动，应先人工检查旧规则，不会自动替换或删除。节假日/临时调课用既有「单日变更」。

API：POST `/api/v1/timetable/preview`（text、firstMonday、timezone）返回课程、日期、规则、新增/重复数与planningRevision；POST `/api/v1/timetable/import`额外传expectedRevision与Idempotency-Key。两者均须主人会话和CSRF。预览版本过期409；导入在一个IMMEDIATE事务内完成，失败整体回滚，相同幂等请求重放原结果。

边界：此版不是图片OCR、Excel/PDF/ICS解析，也不自动按课程生成自主学习窗口或调整现有任务。每条日常提醒仍由任务设置控制，不自动为课程开启邮件提醒。

验证：5项针对性测试覆盖离散周真实展开、单双周/离散节次、错误输入、重复跳过、过期拒绝、事务中断回滚与幂等重放。上线和真实课表入库证据另记进度，不将本说明当成部署完成证明。
