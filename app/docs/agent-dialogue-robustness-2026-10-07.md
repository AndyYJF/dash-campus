## 问题与修正

| 问题 | 修正前 | 修正后 |
|---|---|---|
| 定位卡不能自然语言续答 | 问“在回答哪个”后说“第二个”，再次生成定位卡 | 唯一定位卡接受序号/选项原文，推进所选原问题；“作为新的要求”保留原业务问题 |
| 显式问题在推理中作废 | 可能把答案套给剩下的另一条问题 | 直接检查指定 ID 的状态、会话与来源投递；失效停止，不转答别的问题 |
| 待答超过十条 | 最早十条挤掉最新问题和定位卡 | 上下文取最近十条，组内旧到新；显式 ID 不受窗口限制 |
| 直接答清业务问题后旧定位还在 | 后续短答可能落错对象 | 收起相关定位卡和未定位旧回答，旧“可以”不会被再次执行 |
| `/安排` 一次七件事 | 第七件静默消失，结果和核验仍称全完成 | 保留六件执行上限，明确列出尾项未处理；结果、目标、核验均为部分完成 |
| 换了日期仍沿用前一天下午 | “今天下午3点…，明天9点…”变成明天21点 | 换日期清掉前日半天和结束钟点，重新按该日上下文解释 |
| 24小时钟点被重写 | `08:00` 可变成 `20:00`；`24:30` 变成 `00:30` | 无上午/下午前缀的 `HH:mm` 按24小时制；24:00仅可结束，非法钟点/倒序/跨夜明确拒绝 |
| 回答收尾中断 | 问题已答、恢复 job 已写，但回复结果可能失败 | 绑定、回答、恢复和收尾放同一同步事务；注入失败整体回滚，租约恢复后只处理一次 |
| 旧卡片回答记录/报错 | 失效回答可能先解析或记录原话，返回无效选项而非过期 | 先检查 open/version，409 失效不产生新主人 turn |
| 聊天像结果列表、答案后没回复 | 需要展开历史；卡片续答结果只更新前面的旧结果 | 完整 `/chat` 页与同组件浮层，按消息排列；接受的回答附原问题和当前续办结果，刷新读回 |

`/安排` 是明确命令的确定性快捷路径。不带前缀的自由表达继续由已有模型路由、读取和决策处理；本轮没有替换成关键词系统，也没有绕过执行门、版本与课程保护。

## 真实模型证据

临时独立数据库、合成课表/任务/问题，使用 `gemini-3.8-flash-high`，四流程通过，流程内累计九次模型请求：
