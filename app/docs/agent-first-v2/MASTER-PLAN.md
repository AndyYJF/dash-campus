# Dash Campus Agent-first V2 总规划与工程规格

版本：2.0；日期：2026-10-03；状态：已定稿、可开工的目标规格，尚未实现。

本规格替代旧规划中与之冲突的产品范围、主导航、人工配置和“所有AI变更都需确认”要求。旧工程的登录、权限、可靠投递、恢复控制仍是基础，不因产品改版而取消。执行入口见 [CODING-AGENT.md](./CODING-AGENT.md)。

## 0. 核心任务、边界与完成定义

把工作台重做成单用户、自部署、Web优先的个人学习Agent。用户通过一个入口投递材料或表达意图；系统维护事实、课程、计划、任务与实践证据；用户主要看结果、执行行动、回答少量必要问题。

核心链路：**接收材料 → 理解与核对 → 自动维护事实 → 更新今天/本周 → 实践反馈 → 调整安排和探索方向。**

不是以做完多少模块验收。以下四个场景必须完成真实网页端到端操作：

1. 导入课表，缺教学周时主动问；回答后课程、今日时间线、本周课程占用和规划容量同时变化。
2. 投递混合通知，拆出其中不同事项，按身份判断适用性；明确的个人义务进入行动，条件不明的事项提出一个准确问题。
3. 说“这周复现一个分类基线，预计两小时”，系统提出或自动生成可解释的时间安排；与课表冲突时不会硬塞。
4. 说“今天跑了40分钟，环境一直报错”，时间与卡点记入对应实践；未完成的安排得到调整，方向页显示新增证据，不生成虚假成果。

这些场景无需用户访问旧资源库、课程编辑、项目创建、提案配置等页面。手动纠正保留，但属于例外路径。

### 0.1 已授权的取舍

- 主导航只保留今天、本周、方向；全局统一入口和Agent待答区域贯穿三页。
- 现有Dash业务数据允许备份后重建；原始材料可按明确范围删除。不能把这句话解释为清空整台机器、密钥或所有数据库。
- **旧Todo必须保持可用，其数据库、附件、配置、服务及同步任务禁止写入、删除、停用或改造。** 只读采集，所有派生状态留在Dash。
- 不做多用户SaaS；不做Android原生、小组件和离线冲突同步。保留API能力，Web/PWA轻量安装可后续安排。
- 不接无限工具调用Agent框架。用有限状态机、结构化模型输出和白名单操作组成可恢复Agent。
- 本次任务只产出规划与开发文档，不执行清库、停服务或上线。

### 0.2 当前工程基线与证据范围

本地项目是 `dash-campus/app/`，不是 `andy-blog`。代码核对时为Next.js 16.3.6、React19.2.8、TypeScript、CSS Modules、better-sqlite3、Zod，web和单worker共享SQLite WAL。

最近实际交付是schema16，发布 `20261003-5b6c71b38362`；已导入真实课表，另有旧Todo迁移及校园通知桥接。当前文本模型适配是openai-chat，不足以证明视觉或OCR能力。SMTP已做连接认证和预览，accepted不等于实际入箱。以上为最近核对基线，开工时按本地源码和运行状态更新，不盲信README仍指向前一发布。

已知缺口：课程只是fixed_events，学习窗口为空时容量未知；周负担只汇总计划周任务估时；没有实际用时模型；课表、今日行动和复盘没有完整用户流程。V2不能只改菜单来掩盖这些缺口。

## 1. 用户体验与页面契约

### 1.1 全局入口

桌面首屏可见“把材料或想法放进来”，手机顶部一个输入入口；支持文字、粘贴截图、拖放文件、链接，可混合上传。无需选择“这是课表/通知/记录”。

输入占位示例：“课表、通知、项目想法，或者说说你今天做了什么。”允许用户附带指令，如“只收资料，先别安排任务”。来源接入也必须进入同一处理管线，不再产生另一套校园通知工作流。

提交立即显示“已收到”，随后可见“读取材料/整理内容/安排时间/需要补充/已更新”。这不代表同步完成。离开页面后继续处理；重新打开可看到同一条记录及结果。

每条处理结果最多展示：更新了什么、下一步是什么、必要问题、撤销入口。详情才显示原文、逐字段来源、识别结果和执行历史。禁止主界面暴露job、epoch、读集、JSON等实现词。

### 1.2 今天 `/today`

首屏同时回答状态和行动，采用紧凑状态带与双栏：

- 状态带：日期/教学周、今天课程占用、剩余规划容量、本周重点；容量未确定时显示“暂估”或“需要确认”，不显示伪精确分数。
- 左栏：课程和已安排学习的同一时间线；“下一步”最多3项，列出何时、做什么、为什么。
- 右栏：最多3个当前必要问题、最近自动更新、卡点后续。完整处理记录在抽屉查看。
- 每项学习行动提供开始、完成、稍后；允许一句话记录反馈。开始不是强制打卡。
- 不展示无意义的长期逾期清单；不可安排事项显示具体原因和可选下一步。

### 1.3 本周 `/week`

七天统一时间轴，课程、生活保留、已安排学习、候选空档可对照查看。显示教学周编号、课程占用、学习预算、已排学习、未排需求、已记录实际学习和剩余未来容量。

点击空档可直接说“这里安排微积分”；点击活动可说“这次停课”“移到周五”。保留小型纠错表单，但不要求用户维护多个配置页面。

周总结位于页面下方，包含事实、偏差、下一周调整。AI评价必须有实践出处；“完成3项任务”不能推出“已掌握机器学习”。

### 1.4 方向 `/direction`

默认显示当前1个主要探索方向、最多2个候选、正在进行的实践、成果和待验证问题。允许不确定或暂未选方向。

首次根据用户明确身份和科研/保研倾向初始化探索假设；倾向不等于确认职业结论。每次推荐项目必须说明与目标联系、前置条件、预计第一步、来源及如何验证是否适合。用户选择投入后才建立项目；系统不能因为看到比赛就自动承诺参加。

### 1.5 旧界面处理

| 旧功能 | V2处理 |
|---|---|
| 课表/可用时间编辑 | 改为统一入口输入，详情纠错；时间偏好首次轻量确认 |
| 收件箱/资料库 | 合并到材料详情和结果搜索；主导航移除 |
| 任务/目标/项目CRUD | 保留领域能力，日常操作从自然语言或行动卡进入 |
| 提案列表 | 转为具体待答/选择卡；低风险自动变更不再逐条批准 |
| 日志/成果/复盘 | 输入自动关联、完成反馈、方向证据和周总结 |
| 探索话题/模板 | 方向页内部工作流；不要求配置定期任务才能使用 |
| 邮件/投递/AI预算 | 默认合理，系统设置保留高级入口及故障详情 |
| 导出/备份/恢复 | 保留可靠能力；新增模型必须纳入导出与完整恢复 |

旧 `/plan` 重定向到 `/week`；`/explore`→`/direction`；`/inbox`和`/reviews`→相关周页或活动详情入口。旧API先兼容，待新UI和桥接无消费者再退休。不能同时保留两套独立事实或排程。

## 2. 自动化策略与主动提问

### 2.1 自动化等级（以操作性质决定，不用模型自报confidence作唯一开关）

| 操作 | 默认行为 |
|---|---|
| 存原文、提取明确字段、归类资料、追加明确记录、同来源去重 | 自动执行，提供结果和撤销 |
| 用户明确指令：新增义务、完成自己的任务、修改某次课程 | 对对象和关键参数核对后执行；歧义则只问歧义 |
| 从通知抽出的明确适用义务 | 创建待办；真实截止按原文保存，默认排程由规划策略处理 |
| 未确认作息、任务估时、方向偏好 | 生成显式假设，用于“暂定安排”，首次确认关键偏好后自动维护 |
| 调整Agent生成、未锁定、未开始且24小时以后的学习块 | 有效策略范围内自动调整；用一条摘要说明变化 |
| 调整24小时以内的安排、用户手动锁定安排、进行中的学习 | 不自动移走；生成具体选择，用户回答后执行 |
| 改正式截止、选项目投入、报名、付款、向他人发消息 | 不能从推荐推断授权；V2无相应外部执行工具 |
| 清业务库、永久清原件、改密钥/主机、写旧Todo | Agent日常工具中禁止；数据重建只在独立运维流程 |

“默认自动”不是每天重新排列全部任务。自动排程首次出现时展示一次简短政策：“未锁定且24小时后的学习安排可自动调整”；已明确要求自动安排的用户无需逐条确认。对新自部署用户由初次确认政策启用；未启用时可生成暂定建议，不能伪装成确定安排。

### 2.2 事实、假设、意图分开

每个关键值存 `origin=explicit|derived|assumed`、证据引用、确认状态、版本。学习资格、正式deadline、身份等不能从assumed自动转成explicit。

“我想科研”是偏好；“我已被某实验室录取”是用户陈述；“这个项目可能适合你”是建议。模型输出只能生成候选事实/操作，规则引擎决定能否入库。

明确但低风险的事实允许先保存，再解释；涉及周次锚点、时间格式、源内容冲突时必须先解决，再做依赖该值的排程。

### 2.3 提问结构和生命周期

问题记录必须包含 `questionKey`、所缺字段、为什么需要、所影响item/operation、可选答案、可自由输入、版本、状态。状态为open/answered/deferred/superseded；不提供无理由的“请确认所有信息”。

- 同一缺口（如学期首周）最多存在1个open问题，多份材料共同依赖它。
- 一轮优先显示最多3问，不因无关缺口阻断整份材料。
- 用户可说“先放着”，只暂停依赖分支；后续新材料补齐时问题自动superseded，不能继续追问旧问题。
- 答案先保存为事实和回答事件，再入队恢复；进程中断仍可继续。问题expectedVersion防过时回答。
- 回复可以在问题卡或统一入口；归属不明确时不得猜答给某个问题。
- 教学周示例：“现在第5周”结合这条输入/答案提交时的实例日期/时区推算首周，再展示推算；回答发生在另一周时不能沿用最初材料收到日。若问题已明确写出参照日期，则按该日期；如果上下文是旧截图/引用，需确认参照日期。
- 不把“用户没回答”当作默认答案或同意。

## 3. 统一输入协议和支持范围

### 3.1 本次V2必须支持

| 输入 | 处理方式与验收 |
|---|---|
| 普通文字/粘贴表格/SDCT1 | 确定性解析优先，模型辅助理解；可生成多种item |
| PNG/JPEG/WebP截图 | 同一入口识别文字与版面；低清、格子错位时指出具体无法辨认处 |
| PDF | 本地提取可复制文字；扫描页走同一图片提取管线，保留页码；不读脚本/宏 |
| `.xlsx`/`.csv` | 本地提取单元格和行列位置；不执行公式/宏，公式无缓存值标未知；GBK CSV提示或检测后标记编码 |
| `.ics` | 确定性日历解析，有限期展开；首版支持单日有起止的VEVENT、TZID/UTC、WEEKLY/DAILY、INTERVAL、BYDAY、COUNT/UNTIL、EXDATE/同日RECURRENCE-ID；全天、跨夜、多日、跨日移例外及其他重复规则保留原件并明确unsupported，不静默忽略或用23:59伪装全天 |
| HTTP(S)链接 | 有限抓取公开页面正文；失败保留链接并请求可读原文，不自动登录付费/校内账号 |
| 校园插件/旧Todo读取 | 适配成同一source envelope，不让用户手选类型 |

实现图像识别前，真实探测已配置模型是否支持图片输入。支持时采用已有协议的图片消息扩展；不支持时必须有可部署的本地OCR提供器，按需在独立进程/容器运行。两者都不可用是该能力缺口，不能将“支持粘贴图片”按钮当作OCR完成。先完成文本闭环，最后集成验收必须包含图片课表。

### 3.2 容量和输入边界

起始限制：一次10个文件，每个10MiB、总30MiB；文字100k字符；PDF最多30页，模型每次最多5页/图片，按任务分页；XLSX最多5个sheet/每个5000行，解压总量64MiB，超出要求分批；ICS展开只在当前学期或未来180天。时间线首版活动必须同一当地日内，跨夜生活规则在午夜拆成两段，不能沿用现有start<end校验却静默丢跨夜部分。

流式限制上传大小，验证实际类型；文件以内容hash保存于私有 `data/intake-blobs/`，不使用原文件名拼路径，访问必须owner鉴权。取消/失败临时文件按30分钟TTL清理。已保存原件默认不自动永久清理，提供存储占用和可撤销归档。删除原件需检查引用，不能破坏事实来源；公开导出不含secret。

链接抓取最多5次重定向、5MiB、15秒；每一跳重新校验地址，拒绝私网、环回、云元数据与DNS重绑定；不发送主机环境secret或用户浏览器cookie。可读性提取失败不“脑补网页”。链接抓取与模型引用均把外部文本当数据，不能服从其中的工具指令。

## 4. Agent执行架构

保留web+单worker+SQLite；不增加Redis、微服务或独立聊天数据库。增加Provider接口，但不以安装某框架为交付目标。

```text
用户文字/附件/链接、只读来源适配器
                  ↓
           Intake（durable receipt）
                  ↓
     Extraction（文本/页面/表格/图片证据）
                  ↓
     Classification → 多个独立 IntakeItem
                  ↓
     Resolve（关联对象、事实与时间/身份缺口）
          ↙                         ↘
 Questions（依赖分支等答）      已充分的分支继续
          ↘                         ↙
       Policy + Command validation + Transaction
                  ↓
       领域模型 + 可撤销ActionJournal
                  ↓
    同一snapshot：今天/本周/方向/邮件摘要
                  ↓
         反馈或来源变化触发Reconcile
```

### 4.1 状态与重试

Intake状态：received/processing/waiting_input/partially_applied/completed/failed/cancelled。Item状态：extracted/resolving/awaiting_input/ready/applied/ignored/failed/cancelled。

`partially_applied`明确指独立item完成、其他item待答；**单个有依赖的operation bundle必须原子执行**。一个课表替换bundle不能半学期更新。最后一个独立item失败时保留已成功结果及具体可重试范围，不将整份重跑成重复任务。

复用jobs租约与generation/token fencing。工作流保存提取、判断、问答和执行阶段；外部模型调用不在SQLite事务里；回答后从Resolve继续，不再重复OCR和读取已存材料。丢失租约或用户取消不得提交新变更，已applied部分按journal保留且可撤销。

默认单intake最多4次模型请求（含1次结构修复）、2次链接抓取、最多50个item。大文件分批入队共享intake总预算，不能通过拆子job突破限制。失败可显式重试，默认最多1次瞬态自动重试。OCR独立deadline每批90秒，模型45秒，每批总180秒；分页超出预算给出已处理/待处理范围。

### 4.2 模型与白名单操作

模型返回严格schema：itemKinds、字段与证据、对象候选、missingFields、suggestedCommands及解释。不执行返回的SQL/shell/URL工具调用；操作参数用Zod及领域校验再次核对。

日期Resolve：绝对日期保留年月日及来源时区；“明天/本周五”来自通知时以可信发布时间为参照，来自用户当前指令时以该条提交日为参照；来源发布时间不明且影响截止时主动问。截图无年份不能根据服务器日期伪造年份。已过期或结束材料保存为历史，不自动创建今天逾期任务或补发过去提醒。

首版命令：upsert_course_set、apply_event_exception、upsert_source_notice、create_or_update_task、record_practice、attach_artifact、update_preference、select_project、complete_task、plan_sessions、reschedule_sessions、archive_entity。

每个命令带 commandId、来源item、policyVersion、instanceEpoch、预期实体版本/时间revision、证据引用和目标字段；目标对象由服务端解析候选ID，不能让模型用任意ID改跨范围对象。资格三值仍为true/false/unknown。

## 5. 数据模型与单一事实来源

### 5.1 复用与新增

任务、项目、目标、原文通知、日志、成果继续复用；日常UI不暴露其CRUD结构。新增表按以下责任划分，DDL开工阶段细化索引/FK/CHECK，不得用一个没有schema校验的“万能JSON实体”代替。

| 模型 | 最小字段/约束 |
|---|---|
| intakes | id、channel、text、received_at、reference_date/timezone、status、version、instance_epoch；请求幂等独立 |
| intake_attachments | intake_id、blob_hash、media_type、size_bytes、original_name（仅展示）、extraction_state；同intake/hash唯一 |
| extracted_documents | id、attachment/source、extractor_version、text/hash、page/cell/region locator、status；不能丢原出处 |
| intake_items | id、intake_id、stable_item_key、kind、validated_payload、state、evidence_refs、version；intake/key唯一 |
| clarification_questions / answers | question_key、field_path、dependency_refs、status、version；answer原文/结构值/提交时间；open key唯一 |
| semesters | id、first_monday、total_weeks、timezone、fact_origin、source、version；首日须周一 |
| course_sets / courses / meetings | 学期、课名/教师/地点、选中周数组、节次/时间、来源、版本；同一course_set维护投影 |
| course_meeting_projections | meeting_id、fixed_event_id、source_version、rule_hash；投影归属明确，同meeting/hash唯一 |
| entity_source_links | entity_kind/id、source_namespace/external_id/revision/item_key、field_path/evidence；保留不同来源关联 |
| planning_preferences | 起止时段、休息/餐饮/交通保留、日上限、块长度、缓冲、来源/确认状态、version |
| tasks扩展 | effort_mode=deliverable/time_budget、remaining_estimate_minutes nullable、estimate_origin、estimate_evidence；保留原始estimate，不用实际分钟冒充剩余需求 |
| plan_sessions | id、task_id、UTC起止、timezone、状态tentative/planned/in_progress/completed/skipped/superseded、locked、生成batch、version |
| practice_entries | 日志/任务/项目、occurred_on、actual_minutes nullable、分钟来源timer/user_reported、blocker、artifact_refs、version |
| focus_sessions | task/practice关联、started_at/stopped_at、paused_duration、状态；一个实例最多1个进行中；不能把后台开着当连续学习 |
| agent_action_batches / changes | 原因、来源、readset、policy、epoch、applied/undone、before/after与版本；撤销粒度bundle |
| entity_revisions | 尚无专用history的实体快照；(kind,id,version)唯一；已有logs/artifacts/resources journals复用 |
| source_cursors / source_events | namespace、external_id、revision/hash、接收/是否纳入行动、baseline；namespace/id/revision唯一 |
| workbench_snapshots | 非必需缓存，snapshot_revision/asOf/period，必须可重建，不能当第二份事实 |

blob表按hash去重可加独立blob索引，附件引用不复制文件。所有新表明确列入业务导出或运行内部排除；完整恢复包含原件和引用，旧“只有SQLite”的备份契约必须扩展，不能声称DB备份已覆盖附件。

### 5.2 课程、任务与学习块权威关系

- courses/meetings保存课程语义与原始周次；确定性投影到fixed_events，关联投影源ID。UI只改课程模型，不能再独立编辑投影造成分叉。
- 手工非课程活动仍使用fixed_events；课程单日例外复用例外表并映射课程来源。整套替换须识别学期/来源，冲突时问“替换本学期还是新增另一个学期”。
- plan_sessions成为多次学习排程的唯一来源。旧tasks.scheduled_start/end只供旧记录兼容读取，在切换后新排程不再双写；旧已排程任务迁成一个plan_session。
- 任务估时是需求，session时长是安排，practice实际分钟是已记录投入，三者不能混算。
- 大任务分块仍指向同task；“取消一个学习块”不等于取消任务；完成某次session不自动完成整个任务。
- due仍是事实截止，不能为了让计划好看自动顺延。

剩余需求语义：“本周学两小时微积分”是明确time_budget，可按已确认实际投入扣剩余额度；“复现基线，估计两小时”是deliverable，耗了40分钟但卡环境不能推出完成三分之一。deliverable剩余需求优先用用户报告/有证据的剩余工作估计，未知保持未知；不能简单estimate−actual，也不能每次完成块就自动再补同等时长形成无尽任务。有卡点时优先安排有产出的最小排障步骤并展示假设。两种类型无法明确区分且影响后续安排时提问；默认deliverable，不把时间花完当成果完成。

compat注意：迁成session的task字段不得再被旧schedule.ts计作另一条排程；所有冲突/提醒/今日查询统一通过排程adapter按迁移标记选择权威源。同日多块、跨周块按session和周交集统计；旧plannedWeek只表示意图归属，不决定排程是否显示，不能让未设置plannedWeek的合法session从本周消失。

### 5.3 去重、冲突与撤销

网络重试用Idempotency-Key；来源消息按namespace/externalId/revision；同材料hash只用于复用blob/提取结果。**不能用“相同文字hash”去重所有用户意图**，例如用户在不同日期说“学了40分钟”应是不同记录。

同来源新revision形成新事实；不同来源相近内容只做合并候选，匹配依据至少时间/标题/来源实体，不按embedding相似就合并两门课。用户明确编辑字段优先，不被来源轮询覆盖。撤销后的来源effect记录留undo tombstone，同revision不能自动重新套用；新revision进入冲突/合并判断。

自动新增、修改和归档必须在同一事务内写journal和entity版本，副作用只在提交后入队。撤销逐项要求当前版本等于该batch afterVersion，否则返回具体冲突并提出补偿操作，不覆盖后来的用户/Agent修改，不将版本号倒退。

课程替换、计划重排、明确任务修改分别形成有依赖的原子bundle。修改触发的异步重排属于独立batch，撤销时同时检查关联版本；不能只撤销课程却悄悄留下无解释的新排程。

## 6. 时间预算与自动安排的算法契约

### 6.1 时间和显示口径

实例时区日历计算，真实时刻存UTC；复用time.ts的DST解析与calendar-occurrences语义。所有快照携带同一asOf与snapshotRevision，页面不得把不同时间点的课表/容量拼成矛盾数字。

设A为基础可安排窗口并集，F为课程/固定活动并集，L为生活保留并集：

`有效学习窗口 W = A − (F ∪ L)`。

不是168小时减上课时间。未给作息时直接展示课程占用，另用显式“暂定”模板估算学习容量：工作日08:00–22:00、周末09:00–22:00候选窗口；早餐07:30–08:30、午餐12:00–13:00、晚餐18:00–19:00；课程前后交通各15分钟；日自主学习上限180分钟；最短块25分钟；20%缓冲。生活区间只与A交集扣除。模板是产品起始假设，必须在首屏清楚标为未确认，可一句话调整；不把用户个人作息当已知。若完全没有可解释模板，容量null，仍显示课表事实与需答项。

程序先区间合并/扣除再计算，不能重复扣重叠课程。每日容量 `C_day = min(W_day分钟 × (1−buffer), dailyStudyLimit)`；周容量是每天容量总和。过去时间不再成为未来容量。按实际date展开周次和取消例外。

显示以下独立数字：

- 课程占用：课程时段并集分钟，含课间；教务教学时长如有则另标净授课分钟，不混称。
- 本周学习预算：C_day之和；来源confirmed/tentative/unknown。
- 已排学习：当前有效planned/in_progress/completed学习块，按本周交集累计；跳过/被替代不计。
- 未排需求：剩余任务需求中尚未覆盖的量；未知估时单列，不当0。
- 实际投入：去重practice已记录分钟，仅称“已记录”，不宣称覆盖全部现实学习。
- 未来可安排：根据当日已消耗预算、未来W和已排未来块计算；先算一次未来预算再减承诺，不能对扣除承诺的窗口再次打折。

实现时每天维护同一budget账本。设B_day为已消耗预算：完成session有匹配实际记录时用实际分钟，否则暂用计划分钟并标estimated；未匹配session的实际记录也扣预算；进行中或过时未反馈的session已过去部分只作provisional预算占用，不伪装actual。任何重合记录只能扣一次。任务实际投入仍只统计实际记录。

设W_future为从asOf至当日结束的W，P_future为当前有效学习块在未来的承诺分钟（包含进行中剩余部分）。按如下顺序计算：

`futureBudget = min(max(0, C_day − B_day), floor(minutes(W_future) × (1−buffer)))`；

`futureCapacity = max(0, futureBudget − P_future)`。

再按未被既有session和必要块间休息占用的实际区间，计算可放入哪些长度的块；数值有剩余但都是碎片时明确“缺连续空档”。已排承诺大于futureBudget显示超额，并按自动化政策提出调整。buffer在预算计算各自时间范围内只应用一次，不能先减P_future再乘buffer。

口径例子（单位分钟）：C_day=100、B_day=30、W_future=90、buffer=20%、P_future=40，则futureBudget=min(70,72)=70，未来容量30；不能把(90−40)×80%=40当容量。未知actual的已完成60分钟session暂扣预算60，actual仍null；随后确认实际40分钟后预算回补20，actual显示40。所有页面/邮件必须共用计算器。

### 6.2 排程流程

1. 固定课程、生活保留、锁定/已开始session先占位。
2. 任务依次考虑：明确截止和必需事项、当前主要目标相关实践、普通待办；同级用既有用户优先级和创建时间确定，不调用模型决定分钟算术。
3. 模型可建议估时、任务分解与目标关联，来源assumed；默认未知任务先建议一个25分钟起步块，未知总工作量仍保留，不能假称已覆盖完成。
4. 已知需求默认块25–90分钟、间隔10分钟；剩余小于25分钟可作为有依据的收尾块。每项最多3个未来块；超过规划周期的需求留待安排。
5. 在未来7天、任务deadline之前选择符合时间偏好和预算的空档。不可放入课程、生活保留、锁定安排，也不可超日预算。
6. “预计两小时”可以安排为2×60分钟或90+30，解释依据。分解子任务需保留原总需求与依赖，不凭空把估时翻倍。
7. 不可安排时返回`deadline_unfeasible|insufficient_capacity|unknown_requirement|blocked_dependency`及具体缺口；提供缩小范围/延后非截止承诺/解除某项锁定等选择，不自动改正式截止。
8. 新材料、课程改变、任务卡点触发重算受影响日期和实体，保持无关安排稳定。默认每日一次未来计划维护；同一状态版本不反复重排。

### 6.3 实践反馈

用户“完成了”可不填实际分钟；一次简短提示可选“比预计短/差不多/长”或分钟，拒绝回答后照样完成，不强迫填日志。只报告相对长短时保存qualitative feedback，actual_minutes仍null，不擅自映射为准确分钟。

“做了40分钟”记user_reported；与同日task的计时或完成记录相近时提示合并/替换，不能double-count。计时开始/暂停/停止均幂等；会话断开不自动无限累计，恢复时问是否继续或按最后心跳截断为待确认。超过4小时或跨日记录先核对，不当实际投入直接接受。

已确认实际记录累计后，至少3个相似任务/同项目样本才用中位数比例调整建议估时，调整范围0.5–2倍；不改变owner明确估时，给出建议来源。样本不足展示偏差，不强行学习个人规律。

## 7. 身份通知、项目探索与主动能力

身份事实来自用户陈述/可靠来源；欠缺影响适用性时提问。明确无关通知收资料不占行动；可能相关标待判断，临近截止可提醒一次需核对，不自动报名。来源摘要不能替代原文资格/日期。

持续读取校园来源：首次仅当前未结束事项进入可行动判断，结束历史作为可查询来源；游标外新增/内容变化进入统一管线。旧Todo明确完成/取消是来源状态，不覆盖Dash自建任务状态；用户明确任务修改永远不回写Todo。

项目探索初期按需或每周一次；当前方向无新增信息时不每天制造候选。最多显示3个有可核验来源的候选；“最近做了什么/是否合适/还有哪些未知条件”必须引用实践证据。方向比较不生成虚假保研概率、能力分数、学院政策或截止。

主动触发清单：新材料、回答问题、课程变化、完成/跳过/卡点、每天计划维护、每周事实总结。事件以受影响实体version/period去重并合并，避免一条输入触发多轮模型互相调整。

邮件只发到已配置主人地址，复用当前可靠投递；默认不开新的每日摘要。V2初次设置用一次简单选项开启或关闭；已开启的旧设置可映射。重要必要问题/真实截止按已确认提醒策略发送，安静时段22:00–08:00默认推迟，紧急截止例外须有明确政策。unknown投递不得自动重发；accepted只展示已交SMTP。

## 8. HTTP和前后端契约

沿用owner session、CSRF、统一错误响应、expectedVersion/Idempotency-Key。GET纯读取，不在渲染时调用模型或改事实。所有新API先写共享schema与响应类型。

| API | 契约与行为 |
|---|---|
| POST `/api/v2/intakes` | multipart或JSON：text/attachments/urls/referenceDate；幂等持久接收后202，返回intakeId/status；不等模型 |
| GET `/api/v2/intakes/:id` | 各item/阶段、已更新实体、必要问题、结果版本、来源，不暴露secret与lease |
| POST `/api/v2/intakes/:id/retry` | 幂等，expectedVersion；仅重试失败/未执行分支，不重放成功effects |
| POST `/api/v2/intakes/:id/cancel` | expectedVersion；取消未应用部分，保留已有结果和撤销入口 |
| GET `/api/v2/questions` | open必要问题去重、分页；首页最多3个 |
| POST `/api/v2/questions/:id/answers` | 幂等+expectedVersion，保存回答202并恢复依赖；已答同请求回放，冲突409 |
| GET `/api/v2/dashboard?date=` | 统一snapshot：today/week/nextActions/questions/recentChanges；可先一个聚合端点 |
| GET `/api/v2/week?monday=` | 时间线、预算账本、未排原因、事实总结；共享snapshot算法 |
| GET `/api/v2/direction` | 目标假设、实践、证据、候选与资格未知，不做副作用 |
| POST `/api/v2/actions/:batchId/undo` | 幂等+expectedVersion/readset；不适用部分回滚时返回冲突，不静默半撤 |
| POST `/api/v2/sessions/:id/{start,complete,skip,lock}` | 命令schema、幂等、版本；实际分钟可为空；complete只完成学习块，明确任务完成走同一白名单complete_task并取消无用未来块 |
| GET `/api/v2/sources` | 只读健康、最近采集、来源范围；配置藏高级设置 |

上传授权和完成语义：落文件临时名→校验→稳定blob位置→db记录，异常清临时/未引用孤儿；引用提交失败不算received。既有blob重复引用不可删。响应错误含具体item/字段，422不入队，413报告尺寸，409要求重新核对，503原文仍保留并说明provider缺失。

202只表示接收，状态读取得到completed才显示更新完成；SSE可选，首版用2秒轮询活动任务、结束即停、后台标签减频，避免引入新基础设施。

## 9. 重建、部署与Todo保护

### 9.1 建议迁移方式

采用同仓库、独立V2数据库的重建式切换，减少对旧数据结构的迁就；代码继续按17起顺序增量迁移，旧schema16可按全迁移建新库。**首版不直接DROP旧表或清当前生产库。**

1. P0列清受保护Todo边界、Dash容器/数据/桥接及当前部署状态；只对Dash自己的桥接入口做暂停，不停止Todo服务或影响它所用的上游组件。
2. 停Dash web/worker/桥接，备份当前DB、附件/快照、env配置位置说明及匹配镜像；凭证不入Git，备份私有。
3. 开发与验收使用独立数据目录及fake/provider最小模式；复用代码，不复制生产密钥到测试页面。
4. 新V2库仅种必要owner登录信息、确认身份偏好、课程与来源配置。保留secret在env；重建question/job/delivery队列，不搬旧在途邮件。
5. 当前课表作为带来源的课程集迁入；旧任务默认只读关联当前未结束事项，历史不批量灌成待办。用户允许空库重建时可只保留基础配置和课表，旧Todo随时只读补充。
6. 每次重建递增instanceEpoch；旧job、旧bridge token/请求、旧问题、旧幂等键不得写入新epoch。恢复令牌绑定新Dash source；变更只涉及Dash目标端。
7. 切换V2镜像和DATABASE_PATH，验证聚合页及真实课表、worker/桥接；成功后旧Dash库保留私有至少一个可回滚周期，不立即永久销毁。

只读Todo保护：不得执行UPDATE/DELETE/DDL/VACUUM/修复/清理旧库；不得将旧目录挂载rw给V2；快照使用SQLite readonly connection或只读在线备份方式，不能靠写锁/停Todo获取静态文件。轮询只能GET。删除Dash派生实体时，Todo映射tombstone留在Dash，不级联到旧源。

旧Todo本身可能持续变化，不能要求运行中的字节hash恒定作为验收。用禁止写能力的adapter、只读连接/挂载、失败写测试以及来源行为日志证明本次代码没有写旧源；做任务状态抽样，不把用户自己修改当成破坏证据。

### 9.2 恢复与排程安全

V2备份必须覆盖SQLite+blob hash manifest+需要保留的运行策略，不把.env密钥暴露到业务导出。恢复到隔离目录后重建投影，验证FK及引用文件；继承restored_hold，暂停模型/抓取/邮件/来源拉取直到明确resume。

代码回退但schema相同时保留当前库，避免丢最近入库信息；schema不匹配时恢复匹配备份，说明差异数据范围。回退原Dash还需恢复原桥接目标和游标，绝不操作Todo服务。

最近VPS磁盘余量已低至约178MiB（最近部署观测，开工复核）。不要直接增加大OCR镜像和重复构建。P0给出容量方案：优先离机构建；仅清已确认属于Dash的旧构建缓存/旧发布，保留当前+匹配回退和数据备份；禁止全局docker prune。上线上传/OCR前预留至少1GiB工作空间，达不到则限制接收附件并报告具体能力缺口，不伪装支持。

## 10. 分阶段任务、依赖和交付

按P0→P1→P2→P3→P4→P5→P6推进。阶段完成必须已有用户可见结果，不接受只建表和新目录就标整个阶段完成。每阶段更新progress/decisions/验收证据，不每改一行就跑全套门禁。

### P0 基线、运行边界与迁移准备

交付：当前代码/数据/部署状态表、Todo保护清单、V2独立数据路径、原数据备份/回退方案、provider图片能力实际探测、存储容量方案。

必要检查：读取本地dirty tree保留既有改动；确认迁移最大编号及运行version；新测试instanceEpoch与旧源只读；可用模型不代表图片可用。依赖：无。退出：可安全启动独立V2，不动生产Todo。

### P1 统一接收、证据和主动问答

交付：intake/schema/source/document/item/question持久模型与API，全局入口和处理抽屉；文本/SDCT1/自然语言输入，有限分类器+模型Resolve；答案恢复依赖。

退出：导入混合文字自动拆2种事项，缺课程锚点只问1个问题；无关资料继续保存；回答后重启worker也能恢复；重复网络请求只产生一份结果。此阶段先显示事实和待答，不声称已做自动排程。

### P2 执行策略、实体关联与可撤销变更

交付：policy白名单、entity_source_links、journal/revision、原子bundle和undo；课程语义模型/投影、任务/记录自动维护；已有v1写路径映射到相同命令或限为兼容入口。

退出：用户明确指令自动执行；来源模糊或owner字段冲突准确提问；撤销恢复领域结果且不中断无关变化；后续实体版本冲突不被强行覆盖。未锁定策略可自动更新，硬deadline不被顺延。

### P3 课表、生活预算与学习行动闭环

交付：规划偏好、plan_sessions、practice/focus sessions、确定性时间预算与排程器；同一snapshot，今天/本周新页。

退出：课表导入马上显示课程占用和本周容量状态；初次偏好可一句话确认；2h任务放入合法时段；课表单日变更触发有限范围调整；记录40分钟不重复计时。不得把今日页面作为旧任务清单套新皮肤。

### P4 文件理解与只读来源接入

交付：图片/文本PDF/扫描PDF/XLSX/CSV/ICS/URL provider、本地解析证据定位、限额与blob恢复；校园来源和Todo adapter都进入intakes，默认历史不入行动；后台来源健康。

退出：真实截图课表提取并询问不清字段；文本与文件同内容幂等且不误去重不同日期记录；受限输入明确失败；Todo写操作测试拒绝；重建后不会灌回全部历史或重发旧邮件。

可在P1–P3期间独立准备adapter，不因此延后文字闭环；最终不能跳过该阶段还声称“统一输入已完成”。

### P5 方向证据、每周主动维护与邮件

交付：方向页、按实践证据的候选/下一步，周事实与调整；每天有限重排、每周有限探索；复用可靠投递和owner开关。

退出：无实践时承认缺证据；有真实卡点/成果时建议能引用记录；没有新增信息不反复推送；不自动替用户选科研方向或报名；提醒事实与网页一致，邮件accepted/unknown语义准确。

### P6 切换、恢复、旧界面退休与交付

交付：独立V2库种子/切换和匹配回退、完整DB+附件隔离恢复、旧路线重定向、来源cursor/epoch切换、用户使用说明和最终验收表。

退出：真实owner在新实例完成四个主场景；Todo保持可用且无V2写权限；日常无需访问旧CRUD；遗留定时任务不会继续走旧AI管线重复处理。邮件实测收件需要用户指定收件行为/实际到达证据，缺失则准确标未验证，不妨碍其他已授权工作完成。

## 12. 工程文件落点与禁止事项

新增建议：`src/contracts/intake.ts`、`agent-actions.ts`、`planning-v2.ts`；`src/domain/agent-policy.ts`、`time-budget.ts`、`session-scheduler.ts`；`src/repositories/intakes.ts`、`questions.ts`、`action-journal.ts`、`sessions.ts`；`src/workflows/intake.ts`、`reconcile.ts`、`clarify.ts`；`src/integrations/extractors/`；`src/app/api/v2/`；组件`UniversalIntake`、`AgentQuestionCard`、`TodayTimeline`、`WeekTimeline`、`DirectionView`。

这些是建议责任划分，不要求一次生成空壳。迁移建议按实际最大号顺序拆：intake/questions → provenance/journal/courses → sessions/preferences/practice → source/cursor。每一步同步EXPECTED_SCHEMA_VERSION、导出分类和恢复覆盖。

不得更换整个技术栈、建立第二套通知系统、用一个常驻无边界Agent循环替代jobs、自动重新写所有历史任务、把任意LLMconfidence阈值当授权。不要开发“统一设置管理大全”或把AI聊天加到所有旧表单就算完成。

Windows遵守用户命令习惯：Git Bash，先写脚本再运行；删除不用可能为空的变量；实际删除/移动检查绝对路径归属。避免无关博客改动、无意义审计与全量空跑。未要求则不git commit/push，不把主机/端口/私钥/业务数据放仓库。

## 13. 需要运行时确认而不阻塞开工的事项

- 模型图片能力：P0实际探测，决定vision或本地OCR，不要求用户提前选技术。
- 模型/SMTP/来源secret：复用当前服务端配置；新自部署实例缺配置才提供一次系统设置。
- 默认作息：产品模板不是用户事实；第一次可用时主动核对，用自然语言持续更新。
- 真实邮件入箱：在实施中按既有授权条件取得收件测试输入，不能据历史accepted伪称已验。
- 学校节假日/调课政策：不自动联网猜；原课表与新通知冲突时问用户或取明确来源。

## 14. 防止再次“大而无用”的收敛规则

每个新增功能写出它如何改变今天行动、本周预算或方向证据；三者都不改变的功能不进入本轮。工程可靠性作为支撑完成，不再用测试数、表数、页面数作为产品价值。

交付顺序固定：先文字课表→问答→今天/周时间闭环，再文件和旧来源，再方向主动维护。每完成一个阶段，用真实场景找一次“用户仍需手工调表”的断点并解决，不为补齐原模块清单扩大范围。

最终完成报告分开标记本地行为、真实模型/文件理解、生产切换、恢复、邮件到达。若某项缺证据，写具体限制和保留方案，不用“基本完成”掩盖核心链路断裂。

## 15. 规格审查结论与已消除的歧义

本次采用对规格逐项推敲的方式，不声称运行过尚未实现的V2。已消除会直接导致错误开发的歧义：

1. “自动判断”落实为有证据的多item分类/Resolve；confidence不能独自决定写入。
2. “不确定就问”落实为持久问题、依赖分支、版本和恢复，不要求用户逐条确认所有结果。
3. “自动安排”落实为policy限制、唯一session排程、受影响范围、锁定/24小时规则及无法安排原因。
4. “每周用时”区分课程占用、需求、计划、实际、剩余容量；提供账本公式，禁止把计划分钟当实际或耗时当进度。
5. “统一导入”明确真实provider和支持子集；图片不能停在上传成功，全天ICS不以23:59近似。
6. “允许删数据”限定Dash；新库epoch、独立备份、只读Todo和来源baseline防止误删/历史回流。
7. “能撤销”要求版本检查与原子journal；同来源重放不能悄悄复活撤销结果。

运行时尚待的模型视觉/存储/收件能力已列P0或相关验收，不是缺少开发方向。实施Agent可从P0开始，不需重新询问产品定位。
