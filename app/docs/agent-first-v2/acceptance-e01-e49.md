## 原规格要求的输入类型

| 类型 | 状态 |
|---|---|
| 图片 | 管线已通；真实模型读图未验证 |
| 文本 PDF | 本地取文字，逐页保留页码 |
| 扫描 PDF | 页面图像（PNG）交给图片识别，页码入证据；一次最多 5 张，其余如实列为未处理。**样本是合成的**；只有“一页一张大图”的扫描件能取出，矢量或多图拼页取不出时会如实说明 |
| XLSX | 本地读单元格与行列位置；合并单元格、日期、隐藏表；公式只取缓存值；最多 5 表 × 5000 行、解压 64MiB |
| CSV | 引号/换行/分隔符；GBK 检测并标记 |
| 旧版 `.xls` | **不支持**，准确失败并保留原件（规格只要求 `.xlsx`/`.csv`） |
| ICS | UTC/TZID；WEEKLY、DAILY + INTERVAL/BYDAY/COUNT/UNTIL/EXDATE；同日改单次时间。全天、跨夜、月/年重复、跨日移动的例外**不支持**，逐条说明 |
| 链接 | 抓取正文与正文图片；私网/环回拒绝（含 DNS 解析结果） |

## 接口契约里与规格不同的地方

- `correct_extraction`、`configure_source`、`update_task_priority`、`set_goal_priority` 没有做成独立操作：纠错分散在 `link_resource`（资料归属）、`correct_practice`（实践）、`upsert_academic_calendar`/`apply_teaching_day_override`（校历与补课，主人来源优先）里；来源配置只有 `update_calendar_sync_policy`；优先级并入 `create_or_update_task` / `upsert_goal`。校园通知桥接的令牌仍在设置页管理，不经对话。
- 契约里的读工具（`get_context` 等）没有做成模型可调用的工具：主人的直接指令由确定性解析和绑定器在进程内读事实，模型只拿到有界的分类/提取上下文。页面和外部读取用 `GET /api/v2/calendar-context`、dashboard/week/direction 快照。
- 计时的开始/停止沿用专用接口（`/api/v2/focus`），结果进入统一的实践记录，没有注册成操作。
