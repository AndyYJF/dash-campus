本文件补充 [修复计划](./REPAIR-PLAN-2026-10-04.md) 和 [Agent接口契约](./AGENT-INTERFACE-CONTRACT.md)。继续采用自研、有限步骤的 Agent 编排，复用现有模型适配、jobs、白名单操作与来源版本；不引入外部 coding agent 运行时。

## 1. 用户体验与完成定义

用户可直接向统一入口上传校历图片/PDF、贴学校官网链接，或说：“帮我找四川大学本学年校历，并自动更新节假日和调课安排。”无需先选择导入类型、填写教学周或手工录每个假期。

Agent 识别学校、学年、学期及适用人群，提取学期日期、教学周、考试/假期区间和明确调课规则；已有身份/课表足够时直接应用可核对事实。材料既包含课表又包含校历时分别提取，建立同一学期关联。

完成后的用户结果：

- 今天/本周显示学期、教学周、假期/补课标记、下一节真实课程。
- 停课/补课影响有效课程、交通占用、预算、学习安排和对应提醒；所有视图一致。
- Agent 简述“新增/修正哪些日期、哪些学习安排受影响、还有哪个问题”，提供来源和撤销。
- 用户可继续说“这只是研究生校历”“我们班那天照常上课”“假期我回家，别安排实验”，分别纠正适用范围、课程事实或个人时间政策。

只保存校历链接、画节日标签或识别到标题不能算完成。国家节日标记本身是有用日历事实，但不能冒充已确定学校停课/补课。

## 2. 已核对基线与来源

基线 `cbbaeee` 只有学期首周/总周数、固定活动重复规则、单日例外和课程投影；没有完整校历事件层、国家年度假日数据集或补课日到原教学日的映射。现有 `baseWindows` 以公历周六/周日区分周末窗口，不能直接承担教学调休。

默认以已确认学校为范围，川大只是本实例初始适配；学校不同可从自然语言更新。识别域名、正文主体与适用对象，不因缩写 SCU 就混入其他学校校历。跨学年数据按对应公历年度获取，不能只取秋季开学所在年份。

## 3. 三层事实分离与冲突规则

| 层 | 保存什么 | 允许影响什么 |
|---|---|---|
| 国家/地区日历 | 具体年度节日名称、放假日期、调整上班日期、官方来源 | 公历日标签与已确认的个人假日策略；不直接决定学校补哪天课程 |
| 学校教学日历 | 学期、教学周/阶段、学校放假/停课、补课映射、适用学院/人群 | 有效教学日期、课程实例、考试阶段和相关计划 |
| 课程/个人例外 | 某课程单日取消/补课、班级明确通知、个人休息/旅行/学习意愿 | 指定课程实例或个人可安排窗口；个人休息不改学校课程事实 |

不同层不是互相覆盖的同一个字段。国家“周六上班”只能标记调整工作日，**不推出“周六上周一/周五的课”**。学校明确的补课规则才提供课程映射。

冲突先比较字段、有效期和适用范围，再在相同权限/范围内比较版本与发布时间。某课程已确认的新通知优先于该课程的一般教学规则；同一学校的正式修订可替代旧校历。宽泛新通知不能自动抹掉更具体的课程例外；无法确定哪条有效时保留来源并提一个冲突问题。

用户主动纠正可覆盖个人实例中对应教学字段，但国家官方事实保留原值；界面分别显示官方信息和个人覆盖依据。第三方日历API只可作为线索/缓存，未核对官方来源的数据不自动修改课程。

以下原则必须固定：

- 假期通常不自动暂停或重编号教学周；是否跳周按学校明确周次表执行。
- 开学报到日、开始授课日、第一教学周的周一分别保存；不能见报到日期就设置 first_monday。
- 军训/入学教育/考试周按对象和阶段保存；校历写“考试周”不等于已知某门课考试时间。
- 日期区间含首尾；日期事实用实例时区的本地日期，课程真实时刻存UTC。全日假期不能作为“忙碌24小时”固定活动，导致全天学习容量错误归零。

## 4. Agent 导入与自动获取流程

### 4.1 导入与问答

```text
统一输入/已确认学校触发发现
 → 定位官网校历/通知/国家年度安排
 → 保存网页与附件原件、来源与修订标识
 → 提取结构化日期/周次/人群/映射及字段证据
 → 确定性校验与适用范围核对
 → 必要问题（只缺口，不重复问已有身份）
 → 白名单应用事实与教学例外
 → 重新投影受影响课程、预算与可调整学习块
 → 更新提醒/共享快照，显示结果和撤销
```

模型负责找到和理解规则，不凭空生成节日日期或猜补课映射。校验日期合法、区间边界、学期一致、原教学日存在、映射没有循环/未解释重叠。文字不完整/图片无法辨认时原件留存，问具体字段或请用户核对提取结果，不要求用户重新填整份校历。

学校/本科研究生范围已明确且来源匹配时不用再次确认每个字段。新校历改动首周与既有课程冲突、两张图片属于不同学期、通知只有“调休”无补课映射时，提对应问题。一个缺口不阻塞无关课程/其他材料。

只有国家放假数据时显示该日国家假期，原教学安排标“学校安排待核对”；保留可能课程占用作为保守预留，避免 Agent 把可能上课的时段排满。不得将待核对课程显示为已确认一定上课/一定停课。优先主动查学校通知，仍找不到时只问一次相同缺口。

### 4.2 自动更新策略

- 用户开启自动获取或按已确认学校初始化相应政策后，建立受限来源任务，不要求用户维护URL、cron或provider名称。
- 默认每周核对国家年度安排与学校校历/通知入口；临近相关假期的前14天每日核对已限定的官方通知入口。年度安排一旦核对成功，正常周检查可先读修订/etag/hash，无变化不调用模型。
- 当年数据必查；从10月起检查下一年度公告，跨年学期两年分别获取。未发布则记录未发布/未找到，按周重试，不沿用上一年日期，不预测年度调休。
- 网络失败、403、页面改版、模型失败按有限重试与退避，保留上一版已确认数据；必要时用发布机关的官方转载来源或接受用户上传原件，不自动回落到无出处的日历表。
- 记录 checkedAt、publishedAt、revision/hash、适用年度、原件和提取状态。未获取数据不能显示“全年无节假日”；失败/过期明确区别于已核对无变化。
- 每次只为实际事实变化触发投影/排程/提醒；无变化静默。相同来源revision不重复导入，被撤销版本不被下次同步重新应用。
- 来源更新可自动新增可逆事实；24h内/锁定/进行中学习安排的变更仍遵守授权，冲突给具体选择。来源抓取不因调课而对用户发送未经开启的每日邮件。

## 5. 教学映射、预算与课表的算法契约

日历解释器输入本地日期、学校/学期/人群、课程版本和有效例外，输出 civilDayType、academicPhase、teachingWeek、有效教学日期/来源日期、课程实例及证据链。civilDayType 与 teachingWeek/teachingDate 分开，不修改计算实际星期的基础函数。

课程先按原教学日期和原周次规则展开，再应用明确单日/范围例外。补课映射保存 `targetDate → sourceTeachingDate`，从源教学日课程实例搬到目标日期，保留 sourceOccurrenceId；周次、单双周、仅6/10周等条件按原教学日期判断，不能改按目标日期重新筛选。

如果学校通知写“按某周周五课表上课”，需绑定具体教学周/源日期；无法唯一确定就问。映射可替代目标原课表或增加补课，必须依据来源明确保存 mode；未说明且两者不同会影响课程时提问。若已经用课程单次移动表示同一补课，不再叠加全校映射生成副本。

“停课是否补回、补在哪天”分开保存；课程规则本体不变，只生成有效实例例外。源日课程是否取消取决于来源，不仅因为映射被建立就自动取消；批量应用每个原始实例最多一个有效投影，多个补课去向需明确来源支持。

预算消费解析后的实际课程实例和交通，而非原始公历weekday重复活动。固定活动（体检/会议等）保留原日期，不能跟着课程调休整体移动。更新只重算受影响日期，旧投影与新实例不双扣。

个人假日策略由 Agent 首次提出具体建议并用自然语言确认：沿用周末学习窗口/减少学习/不安排，或另有个人规则。节假日放假不自动把学习预算变零，也不把全天空闲塞满；法定补班不自动把个人窗口改成工作日模板。显式个人日期覆盖优先，再应用确认的假期策略，再回退工作日/周末模板；政策暂定必须标明。

旅行等个人不安排区间才进入生活保留，已确认的不学习日 budget 为0。学校停课只释放课程占用；用户的日上限、已消耗和未来承诺仍约束剩余学习，正式任务截止不因假期自动顺延。

## 6. 数据、工具与接口对齐

建议新增有版本的 `academic_calendars`、`academic_calendar_events`、`holiday_datasets`、`holiday_days`、`teaching_day_overrides`；结合实际模型确定最小表数。保留原件、sourceId/revision、证据位置、适用学校/人群/学期、类型、日期区间、映射mode、状态、覆盖依据、entity version。教学周表可按规则或显式映射保存，不强迫所有校历都线性weekIndex。

复用 semesters 与课程权威层；学期日期修正是一条有依赖的版本变更，不能暗中创建第二个同学期并让课表失去关联。假期日标签不存成24h fixed_events；课程投影仍以同一有效实例为权威。新数据纳入导出/恢复/hold/undo及来源tombstone。

Agent 注册读工具：`get_calendar_context`、`discover_calendar_sources`、`get_calendar_sync_status`；写/触发操作：`upsert_academic_calendar`、`sync_holiday_calendar`、`apply_teaching_day_override`、`update_calendar_sync_policy`。参数有类型的学校/学年/年度/source引用和目标版本；不接模型给任意SQL/抓取内部地址。

- 统一 `POST /api/v2/intakes` 识别 academic_calendar/holiday_notice/teaching_adjustment 及混合材料，扩展分类与结构化提取，不要求用户先选类型。
- `POST /api/v2/actions` 目标接口调用以上注册操作；自然语言、卡片纠错和未来兼容路由同路执行，不新建独立导入API链。
- `GET /api/v2/calendar-context?from=…&to=…` 为新增目标接口，按范围返回日期标签/教学周/有效课程/来源与同步状态，不返回整个私人历史。
- 今天/本周快照引用同一日历解释器及 revision；来源、政策、课程例外改变均使相关快照失效。UI可展示“假期”“补第N周星期X课程”“待核对”“上次更新”，点开查看出处。
- 现有 `calendar-occurrences.ts` 普通固定活动展开保持兼容；课程使用统一有效课程 adapter。改 `workflows/plan.ts` 的 eventsForDay 以该结果为准，避免旧投影例外和新映射双执行。

## 7. 开发顺序

1. R0 增加校历/假日事实及来源结构；复用真实官方页面/图片建立隔离提取样本，验证字段定位，不先清旧课表。
2. R1 建日历解释器、教学映射与课程唯一投影，再接预算/排程/提醒。用合成调课案例验证原周次语义。
3. R2 接统一输入、通用问题和注册操作；缺源日期/人群问清再应用，不制造无依据课程。
4. R3 增加周轴日期标签、教学周、补课来源及更新状态，桌面/手机一致。
5. R4 增加有限来源刷新、跨年数据、个人假日政策、修订/撤销一致性；实际失败如403必须可恢复。

这是现有修复的依赖补充，不是独立“校历小工具”项目。新配置主要由 Agent 对话维护。继续只读 Todo，不启动本机对话自动化代替产品内jobs。
