## 1. 用户目标与范围

用户主要通过一个入口放材料、表达意图、报告进展；打开页面即可知道今天有什么课、接下来做什么、为什么这样安排。系统维护数据，只有影响结果的关键不确定性才提问。

本次必须同时交付：

1. 真正可用的统一输入及结果反馈，补齐创建、修改、完成、记录、纠错和撤销的闭环。
2. 与时间预算、任务安排共用事实的课表可视化，支持桌面周视图和手机日视图。
3. 根据课程、生活保留、截止、剩余需求、实际投入和已确认偏好生成每日安排；安排稳定、可解释，允许留白。
4. 有限的方向选择与项目起步，让日常行动能回到用户的长期目标。
5. 校历与国家假日/学校调课来源进入统一输入和有限自动更新，教学日期共同驱动可视化、预算、安排与提醒。

追加交互要求：内置 Agent 主动问清关键条件，给出推荐并在已授权范围内决定具体安排；用户随时通过自然语言修改。用户不必自己填写参数、挑选每个时间块或逐条批准低风险变更。

沿用单用户、自部署、Web 优先。不要新增独立课表系统、额外人工配置工作流或无限工具调用 Agent 框架。旧 Todo 数据库、附件、配置、服务和同步任务全部保持只读；Dash 修复不回写 Todo。开发采用独立数据库，不因用户允许重建 Dash 就清空生产。

## 3. 课表可视化：直接成为行动界面

### 3.1 页面组织

- 保留主导航“今天 / 本周 / 方向”，不增加一个与本周脱节的课表配置页。
- “今天”首屏：日期与教学周、下一节课、剩余可安排预算、本周重点；下方时间线与最多 3 个下一步行动，旁边是必要问题和最近变化。
- “本周”桌面：上方周选择与摘要，下方七天时间网格。课程、生活保留、已安排学习和候选空档在同一坐标中展示。默认滚动到当前相关时段，可查看完整一天；不能用固定 08–22 点裁掉真实课程。
- 手机默认显示所选日期的纵向时间线，顶部可切换七天；周统计另置紧凑区域。不要把桌面七列缩到手机，也不要要求横向拖动才能读课程名。
- 本周、上周、下周均按真实日期展开，标示当前日期和时间。教学周来自学期锚点，不能将历史聊天里的“第五周”永久硬编码。

### 3.2 可视化对象与细节

| 对象 | 主视图显示 | 点开后显示/操作 |
|---|---|---|
| 课程 | 名称、起止时间、地点；与其他类型有文字和形状区分 | 教师、节次、教学周范围、单双周、来源；“这次停课 / 调到……” |
| 生活保留/固定活动 | 名称、时段，弱化但可辨认 | 事实还是暂定；单次修正或调整规则 |
| 学习安排 | 任务、时段、计划分钟、状态 | 为什么排这里、目标联系；开始 / 完成 / 稍后 / 锁定 |
| 候选空档 | 连续空档长度，达到可安排条件时才提供操作 | “这里安排……”；区分物理空档、预算不足、偏好不推荐 |

课程占用按起止区间并集统计，含课程内部课间；净授课分钟可另列，不能混称。课程前后交通是独立占用层，有重叠只扣一次，不把交通加入授课时长。

课程重叠不挤成一张卡或悄悄去重：显示并列冲突及核对入口。颜色不能是唯一识别方式，键盘也可打开活动；手机和放大文字时课程名、地点与操作不能互相遮挡。

点击空档打开同一输入入口并附带日期/时段上下文，用户不用重新描述时间。点击课程修改的是课程单次例外；投影固定活动不能成为另一份可独立编辑的课表。首版不要求拖拽排程，防止把易用性工作变成用户搬运卡片。

日期头标注假期、补课及教学周，点开可看来源与待核对项。校历/年度节日/学校补课/个人假日策略分层，国家调整工作日不能直接复制工作日课表；具体契约见 ACADEMIC-CALENDAR-AND-HOLIDAYS。

### 3.3 旧课表与导入处理

1. 盘点 Dash 中旧课程活动的可靠来源、课程标识和原始材料，迁入 `courses/meetings` 后生成投影映射。已有来源可证实时自动迁移；不能只靠中文标题猜课程、教师、周次或学期。
2. 无法还原语义的旧活动仍保留为固定占用并标明“待核对课程资料”，只询问影响排程的缺字段。迁移前后忙碌区间应一致，不出现旧活动加新投影双扣。
3. 课表截图经视觉模型或本地 OCR 提取结构化课程字段及证据位置，再复用确定性解析/投影；“识别到课表”或生成摘要不能算导入成功。用户无需转换成 SDCT1。
4. 缺学期锚点时，若用户提供“现在第几周”，结合输入时刻与本地日期提出具体首周日期供核对；材料所属学期不明则先问，不能默认旧截图是本学期。
5. 周次 `6,10` 只生成第 6、10 周；单双周、停课、调课、跨周移动按实际日期展开。课程更新仅影响相关日期的安排。
6. 重复提交、来源更新、整套替换进入已有幂等/版本机制。新学期还是替换本学期不明确时主动问；撤销能恢复相应课程与关联计划变化。

## 4. 每日安排：约束正确，再进行个性化

“智能”在这里必须表现为安排更贴合实际、变化更少、解释更清楚。模型可以理解意图、建议分解和估时；分钟算术、冲突检查、截止约束与最终排程由确定性程序执行。

### 4.1 时间政策与最少确认

硬约束：真实课程/固定活动、已确认睡眠和不可安排时段、正式截止、锁定或已开始的学习块、日预算、必要交通与块间休息。

软偏好：适合集中学习的窗口、单块长度、繁忙课程日少排、优先相关课程复习、临近课程不安排重任务、喜欢先做难任务或先做短任务。未确认的偏好只能作假设，不能伪装成用户习惯。

首次展示原规格暂定模板的具体内容：候选时间、三餐、交通、日上限 180 分钟、20% 缓冲。用户可以确认或一句话改成“工作日最多两小时，晚上十点后不安排”。不再提供看不到默认值的“作息就这样”按钮。

最多同时呈现 3 个必要问题，按影响排序；缺一个字段不阻塞无关材料和课程展示。偏好未确认时可输出明确标注的建议安排，但不得擅自承诺、触发新提醒策略或移动受保护安排。

### 4.1.1 内置 Agent 的问答与决定流程

Agent 驻留在全局输入及结果区域，可展开对话；从今天/本周行动卡发起时携带所选对象。对话和问题保存到服务端，刷新/换设备后继续，不是只有当前浏览器记得上下文。

流程为：**读取课程与已有事实 → 找到影响决定的缺口 → 提一个具体问题 → 接受自然语言回答 → 更新事实/政策 → 计算可行安排 → 落实并说明变化。** 信息已足够时直接决定并执行，不为凑问答重复询问已有事实。

首次不要求填写问卷。Agent 根据课表先给一个可讨论的建议，例如“周三课比较满，建议只安排一段轻量复习；集中实验放到周末。你晚上一般几点后不希望再安排学习？”随后只补充影响预算或选择的关键条件，最多同时 3 问。180 分钟是暂定起点，不能因为用户没有主动设置就永远当成个人上限。

问题必须说明为什么需要，并接受选项或自然语言：

| 触发情况 | 合适的提问 | 回答后产生什么 |
|---|---|---|
| 作息未知且影响安排 | “晚间集中学习还是周末更适合？也可以说其他时间。” | 已确认偏好；结合课程推荐具体安排，不让用户逐块挑时间 |
| 任务总需求未知 | “报告做到哪一步了？不确定的话，我先安排一次25分钟梳理。” | 有依据的剩余需求或明确起步动作，仍保留未知总量 |
| 需求超过真实容量 | “截止前缺40分钟，建议暂缓无截止的实验。可以这样调整吗？” | 有范围的取舍授权，再计算和执行；不自动改正式截止 |
| 修改对象有歧义 | “你说的是今晚的报告初稿，还是周六的实验报告？” | 绑定一个具体对象，不猜、不新建同名任务 |

用户说“你帮我决定/按你推荐的来”时，在已确认目标和约束内由 Agent 选择任务顺序、拆分和时段，直接形成可执行安排；不再把一堆等价方案留给用户选择。结果只需简述选了什么、为什么、未解决条件，以及修改/撤销入口。该授权不能推导为报名比赛、加入科研项目、修改正式截止或永久解除锁定。

授权范围区分本次调整、今日授权、长期时间政策。例如“今天你看着重新安排”只授权今日相关可调整学习安排；“以后晚上十点后不排”是持久政策。持久授权记录具体边界，不能只存一个 `auto=true`。用户可以随时收窄/撤回，后续自动维护立即遵守新政策。

后续只在关键事实变动、明显不可行或样本支持改变建议时主动问，不每天重做首次访谈。用户暂不回答时保持有效安排，显示具体待定部分，其他工作继续；模型不可用时保留材料和对话，不捏造决定或已执行结果。

### 4.2 单一预算账本

复用并修正原规格 §6.1，不再分别计算显示容量和排程容量。统一快照返回 `asOf`、`snapshotRevision`、日期、预算来源、课程占用、已消耗、未来承诺、剩余预算、可放置区间和阻碍原因。

```text
W = 候选窗口 − union(课程/固定活动, 生活保留/交通)
C_day = min(floor(minutes(W) × (1 − buffer)), dailyLimit)
futureBudget = min(max(0, C_day − B_day), floor(minutes(W_future) × (1 − buffer)))
futureCapacity = max(0, futureBudget − P_future)
```

先合并区间再扣除，过去时间不参与未来安排。计划/实际记录的时间按本地日期切分，真实时刻用 UTC 存储；跨日活动不全算到开始当天。页面、排程、复盘和邮件引用同一计算器。

已完成学习块有对应实际记录时扣实际，否则暂扣计划并标估算；进行中/过时未反馈部分是暂占预算，不显示为已记录实际。关联记录去重必须基于同一活动/任务/时间证据，不能只比较分钟相近。

**补充预算分类规则：** 自主学习预算只纳入确认属于学习的投入。运动、校园事务等活动可占物理时间，不能因为进入 practice 表就计为学习成果或学习预算消耗。固定活动占用与同一活动记录不能再作为自主学习额外扣款；类别不清且影响安排时提问。所有任务都受时间冲突检查，非学习任务另展示时间占用，不能偷用未展示的学习预算。此规则细化原 §6.1“未匹配的实际记录”的适用范围。

展示至少分清：课程占用、今天自主学习预算、已记录实际学习、未来已承诺、还可新增安排。剩余预算大但只有碎片时显示“缺连续空档”；预留休息/机动时间不能显示成系统未完成安排。

### 4.3 任务需求与可安排动作

- 明确截止解析绝对日期、钟点、本周几/明天等，引用输入时间和实例时区。相对日期不因重试改变；“上午前”等模糊范围影响可行性时核对，不能默认无截止。
- `time_budget`（如“本周学两小时”）按确认投入扣剩余；`deliverable`（如“复现基线，估两小时”）由实际产出/用户报告决定是否完成。花了多久不能直接推导完成比例。
- 完成学习块与完成任务分开。用户明确任务完成后，取消该任务未来未执行块及相应提醒；只修改 Dash 派生状态。
- 剩余工作未知时，建议一个有产出的 25 分钟起步动作，标总需求未知。执行后必须结合反馈再决定下一步，不能自动无限续排起步块。
- 有依赖/卡点先安排最小排障动作；不把未解决的环境问题伪装成可继续推进的训练任务。
- 默认块 25–90 分钟，块间休息 10 分钟；明确已知剩余不足 25 分钟可安排短收尾块。未知估时不能为塞入碎片随意缩成 5 分钟。

### 4.4 选择位置与留白

先过滤不满足硬约束的候选，再按以下顺序比较；顺序稳定且不依赖每次模型随机输出：

1. 真正临近截止的必要事项；按可行性和最晚开始时刻避免拖到最后。
2. 当前主目标的有限行动，以及用户明确要求优先的任务。
3. 匹配已确认集中窗口、块长度和连续空档；需要集中投入的动作优先连续大空档，明确短收尾动作利用较短空档。
4. 课程密集日降低额外负担，将无正式截止的集中任务放到更宽裕日期。课程刚结束不等于必须立即复习；只有存在相关任务/已确认复习策略才安排。
5. 保留已有安排、减少跨日移动、控制切换次数；同条件用固定任务顺序和最早可行时段打破平局。

首版采用可解释的确定性排序与有限候选比较，先满足可行性，不引入黑盒“效率分”。调整权重/策略必须有行为案例支持。

实现时将任务顺序、候选区间和比较规则分开：任务按正式截止紧迫程度、明确优先级、目标关联、创建时间与 ID 排序；候选按偏好匹配、减少已有安排变动、减少切换、最早日期/时刻排序。先保证截止前可完成已知需求，再选择偏好；不能因为偏好窗口靠后而错过截止。普通任务先占位造成截止任务放不下时，可回退本轮尚未提交的普通候选，不改变已受保护安排。启发式未找到位置不等于数学上不可行，应区分“未找到合适安排”与“已确认截止前容量不足”。

每天给最多 3 个优先行动，全天时间线仍显示完整有效安排。任务不足、需要恢复或用户没有目标时允许留白，说明“今天无需额外安排”或给一个可选择的起步建议，不能制造一堆必做任务。

安排卡说明具体依据，例如“明天 10 点截止；今晚仅有 45 分钟连续空档，因此先完成报告初稿”。不输出“根据你的个人画像精心推荐”等无信息解释。

### 4.5 稳定性、主动调整与不可行结果

- 默认自动重排仅限未开始、未锁定且距当前时刻超过 24 小时的 Agent 生成块。24 小时内的修改须符合已有明确授权；没有授权则提出具体选择。
- 用户明确要求“把今晚复习挪到明早”可在对象清楚且约束允许时执行，形成可撤销变更；涉及正式截止冲突要先告知并询问，不默默执行不可行安排。
- 新固定课程与近期安排冲突时，保留事实，立即标示冲突并给选择；受冲突安排不再展示为“可直接执行”。不删除受保护安排来制造全绿。
- 只重算受影响日期/实体。相同输入、相同规划时刻与状态应得到无变更结果；新数据只触发必要差异，无关块保留 ID、状态和时段。
- 对 `start == asOf`、进行中、已过期未反馈等边界定义一致，避免既不清理又不占位造成重叠。每日维护不得让旧未反馈任务无限累积或新增副本。
- 预算不够、缺连续空档、截止前不可能完成、依赖阻塞时，输出缺口和最少可选行动：缩小范围、挪动可调整承诺、核对剩余需求。正式截止不自动顺延。
- 累计至少 3 个可比、已确认样本后才用中位数比例建议调整估时，范围 0.5–2 倍；不覆盖用户明确估时，不从点击/停留时长推断能力或精力。

**用户主动修改优先：** 24 小时保护限制 Agent 无授权自行重排，不限制用户随时发出明确指令。对象与时间清楚、可行时，直接修改近期甚至锁定的指定块；解除锁定仅限用户明确要求涉及的块。修改正在进行的块须保留已发生投入并按暂停/继续语义处理，不把历史用时移到未来。

### 4.6 开发时必须跑通的具体日安排

固定当前时刻为 17:15：今日自主学习预算 180 分钟，已确认投入 120 分钟，无未来学习承诺；课程和交通结束后，剩余物理窗口为 17:15–18:00、19:00–22:00，18:00–19:00 为晚餐。今天 18:00 截止的报告剩余 40 分钟，另有无截止的基线实验需连续 90 分钟。

正确结果：报告可排 17:15–17:55；今天剩余学习预算随后只有 20 分钟，不能继续塞入 90 分钟实验。实验在后续可行日期选择连续窗口，若超过 24 小时且满足政策可自动安排，否则给可选择建议。卡片解释截止、连续窗口与预算限制，晚餐和余下休息时间保留。

若报告剩余改为 60 分钟，18:00 前只有 45 分钟物理窗口，明确缺 15 分钟；不能排到 18:15、挪晚餐或改截止来掩盖冲突。提出缩小报告范围或由用户明确调整保留时段的选择。此例同时验证课表、预算、截止和可视化来自同一事实。

## 5. 把输入、安排和反馈真正接通

### 5.1 命令与处理结果

扩展现有白名单命令，实现真实更新而非总是 INSERT：任务创建/修改/完成、偏好修改、课程例外、方向选择与项目起步。对象解析先用实体 ID/明确关联，再用名称和上下文；两个“报告”都匹配时询问选哪一个，不猜。

一次输入包含多个事项时按 item 独立处理；没有关联的实践仍可保存，不因课表缺学期锚点而全部卡住。通知按身份区分已存资料、待判断、个人行动，未应用的 ready item 不得显示为已更新行动。

明确任务保存后触发有依赖的排程与提醒副作用；提醒遵守已确认设置，新增每日摘要默认关闭。事务提交与恢复队列采用已有可靠机制，避免答案已保存但没有后续任务。

结果卡必须包含：实际变更、下一步/阻碍、待答问题、查看详情和撤销。公开适用的 batch/entity 引用给前端，不能要求用户看数据库找 batchId。处理完成通知三页失效/刷新，用同一快照版本读取；异步完成、刷新页面、换设备都能从服务端恢复历史。

### 5.1.1 自然语言修改的必需覆盖

| 用户表达 | 必需行为 |
|---|---|
| “把今晚微积分挪到明天下午” | 定位已有学习块，计算明天下午可行时段；不复制任务；可行直接执行并反馈变化 |
| “今晚不学习了” | 今日剩余自主学习窗口暂时关闭；取消/待重排未执行块，展示截止风险；不永久关闭晚间学习 |
| “以后周三少排点，最多一小时” | 持久更新周三上限，影响未来计划；近期既有超额安排按权限核对 |
| “这次复习只留半小时，实验优先” | 修改具体块/优先级，不默默修改原任务总需求；不能因此越过截止或固定课程 |
| “刚才那个挪到周六，其他不动” | 用对话/所选卡引用消解对象，仅调整指定对象和必要依赖；无关块不漂移 |
| “撤销刚才的调整” | 指向最近适用变更，检查版本；恢复相关安排，发生后续冲突时解释，不覆盖后来编辑 |

“下午”“晚点”“别排太满”由 Agent 结合已确认政策提出具体解释；对象唯一且有可行候选时，选择具体时段并说明，避免为了钟点细节逐次询问。会影响正式截止、长期政策或存在多个对象时才提关键问题。不能把模糊的一次表达永久记成精确日上限。

模型仅输出结构化意图、对象引用、修改范围与建议；执行器重新读取实体版本、政策版本和预算，校验后事务写入。旧答案引用过时安排时刷新决定并说明，不执行过时排程。回答与后续入队原子化；所有自动/主动修改保留变更理由和可撤销 batch。

### 5.2 反馈和计时

输入“做完了”“学了一个半小时”“卡在依赖安装”分别形成完成、实际投入和阻碍；不确定关联对象时问，不把所有表达都变成一条无行动的日志。

计时器优先从行动卡开始，明确 task/session 关系。独立计时保留独立活动；同日分钟接近不能合并数学和羽毛球。疑似重复给可核对合并选项，不要求每条记录都填表。

超过 4 小时、跨日、断线恢复展示具体时段与候选分钟，提供确认、修正、放弃；取消输入不启动计时。只报告“比预计久”时实际分钟仍未知。完成不强制填写复盘，但可一句话留下成果或卡点。

### 5.3 方向的有限闭环

方向页最多 1 个主方向和 2 个候选，显示来源、为什么适合、前置条件、第一步和待验证问题。用户选择“试做”后建立有限项目行动，进入同一预算和安排；不自动承诺参赛/科研投入。

实践证据改变下周建议，而非生成能力评分、保研概率或没有出处的评价。先让一个项目真正能开始，不扩大成推荐内容平台。

### 5.4 全业务 Agent 化与接口对齐

用户不必自行调身份规则、目标/项目、资料关联、复盘频率和提醒。Agent 通过通用问答与白名单领域操作完成主要调整；聊天、按钮、纠错表单和兼容接口复用同一服务、版本、journal、排程与投递副作用。详细操作矩阵、通用结果和 HTTP 适配见 AGENT-INTERFACE-CONTRACT 全篇，不能只增强时间安排的 prompt。

问答从当前学期日期专用解析扩为通用 purpose handler；既有六条命令逐项补全并扩展注册操作。身份筛选保留原文与撤销，项目投入有明确范围，邮件采用已授权主人策略；秘密与生产操作不成为聊天隐式副作用。所有新增操作给实际用户可见结果和纠错路径。

全业务接口以 AGENT-INTERFACE-CONTRACT 第 6 节为对齐清单，新增 conversations/actions 与现有路由适配均标待实施。Card 操作与 v1 兼容写入也需接统一领域服务，不能只接 Agent 路径。
