# “方向”页打磨方案与开发交接

版本：v1.0；日期：2026-10-05。状态：**方案，未实施**。代码核对基线：main `15620e4`。本次只读取本地代码并制定方案，没有登录生产、变更业务数据、提交或推送。

## 1. 要解决的事

主人最初的任务是“人工智能专业的职业生涯规划学习实践工作台”。方向页需要把四年路径、专业认知和实际投入接起来，让用户知道自己处在哪个阶段、这一阶段为什么值得做这些事、下一步可以用什么项目判断兴趣。

本轮已确认：

- 优先看清四年的科研、升学和就业选择；当前偏科研/保研，但保留调整空间。
- 目前对AI具体方向主要是应用层面的认识，例如怎样用好Agent，技术细节了解有限。
- 判断投入价值时，优先了解“平时究竟做什么、自己是否喜欢”和“现在能试什么项目、要补什么基础”。
- 导师、招生政策、机会和行业线索由主人自己记录；AI辅助整理，不承担自动替主人发现可靠机会或确定资格的职责。
- Agent主动寻找并推荐探索项目，主人选择后接入近期安排。
- 延续单用户、自部署、紧凑布局和唯一全局Agent栏；用户主要看结果、做选择，日常少调字段。

完成后的核心体验：

> 我打开方向页，先看清当前阶段和几条可能的路径；选一个能看懂的工作样本，试做一个有限项目；做完后，依据自己的感受和作品决定下一步，而不是凭任务勾选数获得“适合度分数”。

## 2. 当前已经有什么，具体缺什么

以下是源码核对，不代表本轮对生产网页或真实模型的重新验收。

| 现有入口 | 当前行为 | 本轮处理 |
|---|---|---|
| `V2DirectionView.tsx` | 主要goal标题、展开的项目卡、候选、最近实践 | 重排信息架构，补阶段地图和工作样本，减少长列表 |
| `directionSnapshot()` / `GET /api/v2/direction` | 聚合goal、项目、候选、14日实践与规则建议 | 扩充同一快照；GET继续只读 |
| `request_exploration` / exploration jobs | 检索来源、产出最多3个候选 | 保留，引入阶段、基础和想验证的问题 |
| `configure_exploration` | 主人配置的定期探索 | 复用授权和job机制，不另做后台Agent |
| `select_candidate` | 选择后建项目，试做只建第一步，默认两周，并触发已有排程 | 保留幂等，补关联路线和阶段、投入预览及排不上说明 |
| `update_project_state` | 暂停/恢复/结束、改变投入状态 | 保留；转正式投入目前不等于自动续建后续步骤 |
| `record_practice`、`link_resource` | 记录实际投入/卡点，资料角色及项目关联 | 复用，补方向感受与线索关联 |

当前缺口：没有四年阶段结构、没有通俗的日常工作说明、没有阶段与项目的明确关联、没有主人线索专区。项目建议主要是次数/分钟/卡点规则拼接，不能称为可靠的方向评估。

现有UI写“有项目时候选最多2个”，实际快照仍LIMIT3；新方案统一“比较时最多3个”，不拿旧文案作为实现事实。

## 3. 三个概念分别表达

| 概念 | 回答的问题 | 示例及边界 |
|---|---|---|
| 去向路径 | 四年后可能去哪里，眼前为何保留这些选择 | 科研与继续深造、工程与就业；科研是一类实践，升学/就业是去向，不互斥 |
| 专业方向 | 我可能愿意长期解决哪类问题 | 从“让智能系统稳定完成任务”理解相关技术工作；一个应用可涉及多个专业方向 |
| 探索项目 | 接下来通过什么具体实践获取判断依据 | 有输入、工作样本、产出和停止条件的小项目；试做不表示已选定职业 |

不要把一次“会使用Agent”自动推断为选定大模型研究；不要把选了项目自动改成唯一主要goal。长期偏好、专业方向和当前项目分别保存与解释。

## 4. 页面结构

维持现有视觉体系：紧凑状态带、细边框、有限强调色和双栏。全局Agent栏不新增第二份输入框。

```text
方向                                      [让Agent解释当前路径]
当前阶段 · 本学期重点 · 当前去向偏好 · 记录是否足够

大一：建立基础 → 大二：比较与验证 → 大三：深入投入 → 大四：整理成果与下一步
                     点击阶段查看，不会生成一整年的待办

[四年路径] [理解方向与试做] [我记录的线索]

左侧约2/3                                右侧约1/3
当前阶段为什么做这些                     当前试做 / 下一步
本学期1–2个可验证目标                     我的判断及其依据
可以比较的工作样本、探索项目               待回答的关键问题

近期作品与方向复盘摘要；历史记录按需展开
```

三个标签是同一`/direction`工作区的子视图，不增设独立聊天或另一组主导航。

### 4.1 默认“ 四年路径 ”

首屏固定显示四年地图，当前阶段突出；默认只展开当前阶段。本学期优先展示1–2个目标和一个明确的下一步，未来阶段显示目的及选择节点，不把四年展开成任务瀑布。

每个阶段包含：这一阶段想得到什么、共同基础、值得验证的选择、可以留下的成果、下一阶段可能需要什么。不显示“完成百分比”或自动预测保研/录用概率。

| 阶段模板 | 展示目的 | 共同基础与可观察成果 | 去向相关提示 |
|---|---|---|---|
| 大一：建立基础和感知 | 获得专业工作的初步认识 | 数学/编程学习记录，一次能解释过程的小实验 | 保留科研、升学和工程实践选择；先积累认识 |
| 大二：比较与验证 | 区分兴趣、基础欠缺和暂时困难 | 比较两种方法、复现/工程小项目、失败分析 | 通过不同工作样本形成偏好，联系线索由主人提供 |
| 大三：深入投入 | 有限聚焦，持续完成较完整工作 | 项目迭代、可复查成果、本人复盘 | 按主人确认的去向和真实要求补阶段目标 |
| 大四：整理成果与下一步 | 把已有实践用于自己的下一步选择 | 作品说明、研究/工程总结、个人材料 | 具体申请、就业、毕业节点来自主人资料或可核对来源 |

这是可调整的通用模板，不是四川大学官方培养方案，不代表事情只能在对应年级发生。阶段内容可以提前、延期或跳过，不给用户贴“落后”标签。

科研/升学/就业以叠加提示展示：共同基础优先，主人可比较差异。已有“偏科研/保研”的记录会突出相关可验证活动；不会据此生成未经核对的成绩、竞赛、论文或导师硬指标。正式政策、资格、日期不得由模板和模型填空。

已确认的年级、学期可直接复用；缺失时只问当前阶段，不要求完成性格测试或先选具体研究领域。入学年份不足时地图仍能用“大一/大二”表达，不猜毕业日期。

### 4.2 “理解方向与试做”

采用“问题和工作样本在前、专业术语在后”的说明卡。首批只做4–6个有差异的入口，不生成几十个方向名称。

每张方向卡必须能展开以下内容：

1. 用一句话解释想解决什么问题。
2. 典型实践中经常做哪些工作：看数据、设比较、调试、读材料、分析失败等具体活动。
3. 一个初学者能理解的工作样本，连同产出示例。
4. 现在需要的基础；区分已确认、未确认和项目暂不需要。
5. 一个可试做项目及“它能帮你判断什么”。
6. 主人感受与实践证据，允许“还不知道”。

例如“让智能系统稳定完成任务”可以展示“收集失败例子→比较处理方法→解释差异”的工作样本。这个入口涉及哪些方向由内容说明，不假装它对应唯一职业。

说明中的稳定知识由有版本的编辑内容提供，AI负责改写解释与结合上下文；使用最新工具、研究主张或具体资源时必须保留来源。可随时点“讲简单一点”，携带方向上下文进入全局Agent栏。

项目卡从现有候选升级为可比较的提案，列表默认只展示最多3个：

| 字段 | 用户看到的含义 |
|---|---|
| 想验证什么 | 喜不喜欢分析失败、比较实验、搭系统等哪类工作 |
| 实际会做什么 | 2–4个具体活动，不能只写“深入学习”“提升能力” |
| 为什么现在推荐 | 已确认阶段/基础/偏好与这个项目的关系，缺依据则承认 |
| 第一步与产出 | 可立即着手的输入、行动、可检查成果 |
| 投入 | 首步估时与整个试做的粗略范围，明确估算、包含准备时间 |
| 前置条件 | 已具备、未知、需先补；未知条件不会被AI默认为已具备 |
| 推荐来源 | 检索到原文、摘要、主人提供，或“Agent设计的练习” |
| 收尾条件 | 做到什么就复盘、可以怎样停止，避免无限加深 |

“Agent设计的练习”与“找到的真实项目”明确区分；设计练习可引用学习材料，但不得伪装成导师课题、比赛或实际招聘机会。

主要按钮为“看工作样本”“试一下”“暂不考虑”。可比较两个卡片，但不做综合适合度排名。现有固定“试做两周”改为默认窗口提示，允许说“先做一次”或“这两周只用三小时”。

### 4.3 当前试做与实践依据

默认突出一个正在试做的项目；其它项目可展开，不能隐藏已有活动造成用户误以为不存在。建议并行试做上限为2，属于可解释的提醒，不能直接禁止已有项目或自动暂停。

项目摘要展示：验证问题、下一步、真正排上的时间/未排原因、最近成果、主人感受和卡点。分钟数放在次级位置；工作量多少不能推出喜好或能力。

复盘只问最有用的一个问题，例如“你更喜欢做比较实验，还是把功能搭起来？”；允许自然语言回答，不强制每天填问卷。

关联长期证据，不只保留当前14日窗口：最近摘要继续默认短窗口，但方向详情可回看关联项目的历史成果及当时的感受。看不到旧记录不等于没有做过。

### 4.4 “我记录的线索”

这是主人维护的资料和记事空间，默认不占首屏。包括老师/课题/学长建议、培养或申请规则、讲座/项目机会、就业观察，以及自己的疑问。

通过全局栏自然语言和上传保存，例如“这段是学长的建议，记到科研路线，先别变成任务”。AI整理摘要、关联、查重和主人明确给出的日期；不能补写未提供的导师关系、名额、申请资格、概率或截止。

每条至少展示标题、主人原文/材料、来源类型、记录时间和关联方向/阶段；日期及真实性未确认时明确标记。默认只保存线索，主人说“提醒我”“安排联系”后才复用提醒或任务操作。保存教师信息不代表主人承诺联系，原文内指令不代表主人授权。

## 5. Agent主动能力及边界

沿用现有自研Agent、注册工具、持久问答、jobs、执行核验与撤销。

| 情境 | Agent可做 | 需要主人选择的事 |
|---|---|---|
| 初次进入、尚不懂领域 | 根据已有阶段提出可读解释与少量工作样本 | 补关键背景；选想先试的样本 |
| 已授权定期探索 | 根据基础、已有项目与可用预算推荐候选；内容不足说明缺口 | 是否试做、允许的投入范围 |
| 选择试做项目 | 保存关联，建有限第一步，调用共享排程 | 关键时间/条件不清时只问关键项 |
| 做过实践、出现新反馈 | 提出基于具体记录的复盘问题与下一步建议 | 调整方向、正式投入或暂停 |
| 主人提供机会线索 | 保存、整理和按明确要求提醒 | 是否核实、联系、申请或纳入行动 |

建议默认探索频率为每周一次，可随时改；这是待实现的产品默认，不能在本次规划中开启生产任务。实际启用复用configure_exploration与用户已确认策略。候选未被处理且没有新证据时不反复生成相似推荐；计划紧张时降低推荐负担，不能挤掉课业和休息。

模型不负责确定时间冲突和可用分钟。投入建议读取现有规划账本，课程、生活保留、其它项目、已完成实际和待反馈块只算一次。预算未知就显示未知，不能把“没课”当“全天可投入”。

方向判断至少区分：**主人明确说的、实践能支持的、Agent推测的、尚未知道的**。缺技术基础和讨厌某类工作是不同原因；一次卡住不能据此劝主人放弃方向。

## 6. 选择项目到近期安排的完整流程

1. 项目卡先给出工作样本、估算、基础与验证问题，不创建任务。
2. 主人点“试一下”或自然语言选择，带candidate/track/stage的结构化上下文进入唯一Agent栏。
3. 已有信息足够时直接提出有限起步；缺投入边界时问“先做一次，还是两周内试做？”而不是让用户调十个字段。
4. 执行复用select_candidate、createProjectFromCandidate及已有任务/排程服务，写入方向和阶段关联，同一幂等操作不能重复建项目。
5. 返回真实结果：已排的第一步，或未排的原因与下一步；建好项目但没有时间不能显示“已经安排好”。
6. 若容量不足，可提出暂停等待、缩小第一步或改时间。没有明确取舍授权时不挤占其它任务、不移动锁定块。
7. 用户实践后自然语言反馈，实际时间遵守最新反馈记账规则；没有用时不猜。一条反馈可关联已有项目及方向。
8. 到复盘点询问一个有区分度的问题。继续/暂停/转投入复用项目操作；转投入后要有下一步，就经现有Agent显式生成有限步骤，不能仅改engagement后宣称已续排。

方向里的动作按钮用compose现有指令及对象上下文，不增加关键词路由或新输入框。展示工作样本、切换地图和看资料都是只读，不创建“查看方向”学习任务。改口续办、确认、核验、撤销及同步回答刷新保持现有语义修复边界。

## 7. 内容和数据设计：最小增量

所有字段以下是**新增建议**，不是当前接口已具备。实施前核对实际schema最大号；本次基线34不意味着开发时可以固定写0035。

### 7.1 静态内容

新增有类型、有版本的阶段与方向说明目录，例如`src/content/direction/`：

- 四年通用阶段模板，8学期细分可在展开层；模板不当成主人正式目标。
- 4–6个工作样本入口：通俗问题、活动、基础、适合验证的问题、稳定解释的来源。
- 模型解释不能改掉模板原文或事实状态；目录版本随升级可追溯，用户修订独立保存。

### 7.2 建议持久化增量

| 数据 | 主要字段与用途 | 约束 |
|---|---|---|
| `direction_profile` 单例 | confirmedStage、entryYear可空、pathPreferences、basisRefs、version | 阶段来源明确；入学年未知仍可工作；偏好可多选 |
| `direction_tracks` | id、templateKey可空、title、status、ownerNotes、version | status固定exploring/following/paused；试做状态从关联项目派生，不另存第二份项目状态 |
| `roadmap_items` | id、stageKey、title、purpose、goalId可空、trackId可空、status、basisRefs、version | status固定adopted/completed/paused；只保存主人采用/修订的阶段项；未来模板不批量落目标或任务 |
| `direction_project_links` | projectId、trackId、roadmapItemId可空 | 允许一个项目跨方向；同一项目投入统计只算一次 |
| 方向线索关联 | 复用resources/resource_revisions；在resource_links扩充direction/roadmap上下文 | 原文、出处和角色保留；线索默认reference，不自动变achievement或task |
| `direction_reflections` | id、originalText、occurredOn、projectId/trackId/practiceEntryId可空、sourceIntakeId、version | 至少关联一个对象；保存主人原话，关联实际实践时复用practiceEntryId，不再记一份分钟数 |

优先复用资源和实践，不另建一套资料库、作品库或排程表。迁移应完整保留已有项目/候选/实践和资源关系；旧项目暂未关联方向时显示“未关联”，让Agent协助整理，不能猜删或强制分类。

新表和附属字段必须同步导出/恢复白名单、版本化快照及撤销；仅迁移加表但导出丢字段视为未完成。

阶段键固定为`year1`–`year4`，阶段是主人确认的当前位置，不从任务数推算。去向偏好使用可并存的`research/further_study/employment/undecided`；不能把未选择解释为排除某去向。方向状态由主人明确选择，关联项目的trial/committed单独展示。阶段项标为completed须主人明确确认，或满足主人事先确认的具体验收条件；累积小时数不触发完成。

反思不增加强制评分表：原话必留，整理摘要可再生成并标为AI整理。缺日期时沿用现有本地日期确认规则；缺关联时利用对话上下文绑定，仍有歧义就问。AI推测只出现在有证据引用的建议中，不写成主人感受，也不与实际用时重复记账。

## 8. 接口、工具和前端落点

### 8.1 只读快照

扩展`GET /api/v2/direction`，建议新增：

- `profile`：当前阶段、确认来源、去向偏好；
- `roadmap`：阶段模板摘要及采用的条目；
- `tracks`：工作样本、关注状态、关联项目和证据摘要；
- `activeTrials`：试做项目及排程后续，可直接复用projects字段逐步过渡；
- `recommendations`：扩充候选的验证问题、来源类型、估时依据和适用条件；
- `notes`：主人线索摘要与出处；
- `snapshotRevision/asOf`：保留现有统一版本语义。

首屏不请求生成长篇模型内容。读快照不启job、不写建议、不问新问题。细节按需读，历史证据分页；loading/空白/加载失败不能被包装成“没有证据”。

### 8.2 操作建议

新增有类型操作，可命名为：

- `update_direction_profile`：更新主人明确的阶段和去向偏好；
- `upsert_direction_track`：添加/修订关注方向及主人备注；
- `update_roadmap_item`：采用/修订阶段项，必要时引用已有goal；
- `link_direction_project`：关联现有项目、方向和阶段项；
- `record_direction_reflection`：保存主人的实践感受及关联，不能用模型判断冒充主人话语。

扩展link_resource支持方向/阶段上下文。select_candidate增加可选关联字段和试做意图，仍通过同一执行器和关联写入事务落实；重复选择原候选直接返回现有项目。

这五个新操作名称作为本方案的实施契约，不能在前端和模型中各起一套名字。profile更新传变更字段与expectedVersion；track和roadmap创建时不传ID，修改时传ID及expectedVersion；关联操作以对象ID组合去重；反思带请求幂等键，同一回答重试不得重复存原话。支持明确更正和撤销，首次采用模板不得顺带新建goal或task。自然语言“这个方向先不看了”只改track关注状态；“也暂停相关项目”才执行另一个有范围的项目操作。

投入预览是只读计算：用现有共享排程规则评估首步容量并标记估算，不提交临时任务、学习块或规划修订。容量未知显示未知；真正选中后重新读取最新预算执行，不能把预览时间直接当作已预约时间。

这些操作必须逐一覆盖：OPERATIONS、Zod、intent/semantic step、绑定与实体读取、commandEntities、授权/约束门、事实确认、执行、核验、步骤恢复、撤销、只读工具上下文、导出恢复和HTTP返回。不能只注册前端按钮或只改prompt。

知识目录和方向快照加入现有有界get_context/get_entity_detail等读取能力；无法表示的新实体明确扩展枚举，不让模型猜ID。新增参数全部说明来源与版本，原材料内的“主人已确认”不能变成授权。

### 8.3 前端

`V2DirectionView.tsx`保留顶层容器，按阶段地图、工作样本、试做卡、证据摘要、线索列表拆小组件；继续共享api、dashBus、UniversalIntake和现有CSS体系。代码实施前读Next本地文档。

桌面双栏；手机阶段条可横向浏览，内容单栏，比较视图改纵向，不缩成四个难点的小格。方向详情可在页内展开/抽屉，但不能挡住唯一Agent栏。保持键盘、焦点、长文本换行和暗色可读性。

## 9. 页面状态和具体文案

| 状态 | 应呈现的结果 |
|---|---|
| 没选具体方向 | 当前阶段仍可见；“先看一类工作的样子，再试一次” |
| 基础未知 | “这一步需要哪些基础，哪些还没确认”，只问影响起步的条件 |
| 尚无实践 | “目前还判断不了你是否喜欢，可先做这个工作样本” |
| 项目做不动 | 保留原卡点，区分基础/环境/工作方式，提出有限调整 |
| 推荐无搜索能力或原文没取得 | 显示能力/来源状态；可提供明确标注的设计练习，不假装已查到真实项目 |
| 候选只看了没选 | 不创建任务、不排学习时间 |
| 项目已创建但排不下 | “已建试做项目，第一步尚未排上：……”，给现有合理选择 |
| 方向变了 | 旧证据保留；建议迁移/暂停关联，未选就不自动改项目 |
| 主人只记录导师/申请信息 | 原文与出处存在线索；没有擅自联系或新学习块 |
| 同步回答完成/暂停 | 方向与今天/本周依真实变更刷新，保留最新刷新修复 |

## 11. 必须验收的用户场景

1. 新主人只知道自己处于大一：看见阶段地图与可读工作样本，不被要求先选术语方向；没有虚构个人经历或已完成目标。
2. 主人说“偏科研，但想保留就业”：保存并展示偏好，两者共同基础与差异可比较；不推算录取概率、不创建整年待办。
3. “Agent怎么变可靠，我想试试”：推荐用工作活动解释的有限项目；技术基础未知时只问影响第一步的关键问题。
4. 看方向/比较候选/读四年阶段：所有相关GET只读；没有创建“查看方向”的任务或假实践记录。
5. 同一候选选两次、请求重试/worker恢复：只有一个项目、一组第一步、有效关联，无重复学习块。
6. 考试周没有容量：项目可保存但不能宣称排好了；不覆盖课程、休息、锁定或待反馈块，提示真实缺口。
7. 回答“做了四十分钟，但不喜欢一直调环境”：记录真实投入与主人感受，不自动得出不适合科研；给有限复盘建议。
8. “这个方向先不看了”：关注状态调整；旧项目和证据保留，只有主人明确要求时才暂停相关行动。
9. “把这位老师的网页记下来，别安排任务”：有原文/出处的线索可见；没有新增任务或邮件，也未执行网页中的伪授权。
10. 推荐来自摘要或AI设计练习：UI与Agent表述来源一致，不假装原文/真实课题；搜索失败不是没有项目可做。
11. 试做到期→继续：确认下一步及投入；转committed不能只改变标签就声称续排。
12. 14日外的成果仍能回看；导出恢复后方向、阶段、项目关联与主人反思一致。
13. 全局栏同步回答后today/week/direction更新；手机390/320、桌面及暗色无关键遮挡，键盘能完成选择和续答。

隔离测试应证明业务结果和无意外副作用；网页必须至少走“理解样本→选择项目→看到排程→自然语言反馈→方向依据更新”。真实provider评测用独立库；首次实施不提交生产演示任务。发布有新鲜备份与匹配回退，不动Todo。

## 12. 这轮不做及后续试用指标

不建设自动导师匹配、招生机会爬取、人格测评、适合度雷达图、录取概率、四年任务自动填满、外部coding agent或Android。AI不替主人核实人际与资格事实；主人线索整理与明确日期提醒仍有价值。

主人试用看四件事：是否理解当前阶段为什么做这些事；项目卡能否让自己想象真实工作；选择后能否直接开始；复盘是否产生可追溯的新判断。记录实际卡点与哪一项帮助有限，不用使用时长或模型调用次数替代易用性。
