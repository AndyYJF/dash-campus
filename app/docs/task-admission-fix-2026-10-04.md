# 学习排程准入修复（2026-10-04）

## 问题与结果

旧 Todo 的通知、报名决策和购物待办都进入 `tasks`，排程又把所有未完成任务视为学习需求：估时未知时自动生成 25 分钟起步块。课表重投后，七条非学习事项因此实际进入今日/明日学习安排。

修复为独立的业务准入：只有明确的学习/项目工作自动进入学习预算。通知、活动、日常待办、待决策和待确认事项在今日与本周的「待处理」区域保留，截止与提醒不因分类消失。「未安排的学习任务」仅显示已准入任务的容量/截止/工作量问题。

## 接口与业务规则

- schema 29 新增 `tasks.task_kind`：`auto / study / todo / decision / event / notice / unknown`。旧数据默认 `auto`，共享确定性解析器优先识别通知、决策与生活事项；不能只凭估时、截止、项目归属判定学习投入。未识别事项为 `unknown`。
- 兼容 v1 创建/PATCH 和注册操作 `create_or_update_task` 共用 `taskKind` 字段。显式纠正持久化、记录版本与变更，可撤销；不创建同名副本。
- 自然语言示例：「把买miniUPS作为日常待办」「这条只提醒，不安排学习时间」「把这个作为学习任务安排」。从卡片发起时用 `selectedEntityRef` 绑定原对象。逗号不把事项纠正误解析成全局禁学策略。
- Agent 对未知事项提出 `task_kind` 问题。回答按用途解析并落实同一个注册操作，否定句即便包含「学习」也不准入；确认前不生成学习块。最多三个问题，截止/冲突等已有紧急问题优先；明确分类后旧问题失效。GET 快照只读。
- 重新排程撤回未开始、未锁定、自动生成的非学习块，**即便在 24 小时内**。人工指定、锁定、已经开始的块保留。撤回是 `superseded` 并记录变更，不删除任务或伪造实际投入。
- 活动只有确认起止时间后才能经已有日程操作扣减空档；本次不会从标题擅自编造活动时间。通知不表示主人已经决定参加。
- Todo 源数据、附件、配置、服务与同步只读。分类与排程状态只写 Dash。
